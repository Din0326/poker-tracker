# GTO Wizard 上傳驗證檔（SPEC-v2-hands 12.3 H5 第 1 項）

本目錄的 `.txt` 是給使用者以自己的 GTO Wizard 帳號上傳（Hand History Analyzer）的驗證檔，用來確認 Poker Road 的 PokerStars 格式匯出（SPEC-v2-hands 第 7 節）是否被接受、能否分析，以及 7.5、7.6、7.7 標「需驗證」的寫法是否可行。Claude Code 不代為登入或上傳。

- 所有檔案都由專案的匯出程式 `exportPokerStars`（`src/domain/hands/export/pokerstars.ts`）產生，**不是手寫**：手牌資料在 `tests/unit/helpers/gtoWizardCheck.ts`（重用 H3 往返測試的案例），以 `npm run gto-check` 重新產生。
- `tests/unit/gto-wizard-check.test.ts` 會確認每個檔案都能被專案自己的 `parsePokerStars` 解析回來，且內容與目前的匯出程式一致；匯出程式日後變更時這個測試會失敗，提醒重新產生。
- 檔案格式依 7.2：UTF-8 不加 BOM、`\n` 換行、手牌之間 2 個空行、以單一 `\n` 結尾、只含 ASCII。Hero 名稱為預設的 `Hero`。
- 所有手牌都是測試資料，不是真實牌局。

## 建議操作

1. 先上傳 `all-6-hands.txt`，記錄工具顯示匯入了幾手、有沒有錯誤訊息。
2. 若合併檔整個被拒或少於 6 手，再逐一上傳 `01`–`06` 單手檔，找出哪一手被拒。
3. 每一手打開來看：是否能分析（或顯示不支援的牌局格式）、手牌時間、盲注與金額、玩家與動作是否正確。

**特別請確認**（14 節「最需要使用者決定的項目」）：

- 7.5 無時區後綴的標頭時間是否被接受；工具顯示的時間是否與檔案相同（若工具當成美東時間換算，顯示的時間會不同，請記錄實際顯示值與工具設定的時區）。
- 7.6 元單位無小數金額（01、02、04、05）是否被接受。若不被接受，規格的候選做法是元單位也補 `.00`（例 `$100.00`），需更新規格版本後才會修改程式。
