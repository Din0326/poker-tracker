## 1. 產品概述

這是一個自用的德州撲克記帳 App，讓使用者在每場牌局結束後 30 秒內記完一筆，並分類看清楚自己在現金桌、標準 MTT、限時 MTT 的長期表現。形式為 PWA，以 iPhone Safari「加入主畫面」為主要使用方式。

**使用者**：單一使用者（開發者本人），無帳號、無登入、無多人功能。

**目標裝置**

| 裝置 | 優先級 | 說明 |
| --- | --- | --- |
| iPhone Safari（加入主畫面） | 必須 | 主要使用情境，所有畫面以 375–430px 寬度設計 |
| 桌機 Chrome（Windows） | 必須可用 | 開發與備份操作用，版面置中、最大寬度 480px 即可 |
| Android Chrome | 不保證 | 不刻意測試 |

**v1 範圍**

- 新增場次：現金桌、標準 MTT、限時 MTT 三種類型，錦標賽支援同場多筆買入
- 報表：分類頁籤、期間篩選、各類指標、累積盈利曲線、分組統計
- 場次列表：檢視、編輯、刪除
- 賣股份：三種類型都可記錄賣給一位或多位出資者的比例與加價倍數，盈利類指標以你的份額計算（v1.2，4.6）
- 設定：常用場地與盲注級別管理、JSON 備份還原、CSV 匯出
- PWA：可安裝、離線可用

**非範圍（v1 不做）**

- 手牌紀錄（v2）
- 帳號、登入、雲端同步、多裝置共用
- 多幣別：所有金額視為同一幣別（新台幣），不做幣別欄位與換算
- 推播通知、原生 App 打包
- 線上撲克平台手牌檔匯入
- 買別人的股份（你當出資者）；出資者付款與分帳狀態追蹤；出資者管理頁（v1.2 範圍外，見 4.6、11.3）

## 2. 技術架構

純前端靜態 PWA，資料全部存在裝置本地 IndexedDB，沒有後端。部署到任一支援 HTTPS 的靜態託管即可。

**技術棧**

| 項目 | 選用 | 等級 | 理由 |
| --- | --- | --- | --- |
| 建置工具 | Vite | 必須 | 輕量、PWA 外掛成熟 |
| 框架 | React + TypeScript（strict） | 必須 | 型別保護計算邏輯 |
| 樣式 | Tailwind CSS | 建議 | 搭配第 9 節設計 token |
| 本地資料庫 | Dexie.js（IndexedDB） | 必須 | 支援 schema 版本遷移與索引查詢 |
| 表單 | React Hook Form + Zod | 建議 | 驗證規則集中定義 |
| 圖表 | Recharts | 建議 | 累積曲線足夠用 |
| 日期 | dayjs | 建議 | 體積小 |
| 路由 | React Router（HashRouter） | 建議 | 靜態託管不需設定 fallback |
| PWA | vite-plugin-pwa（Workbox） | 必須 | 產生 manifest 與 service worker |
| 單元測試 | Vitest | 必須 | 覆蓋第 4 節所有公式 |
| E2E 測試 | Playwright（WebKit + iPhone viewport） | 必須 | 模擬主要使用裝置 |

套件版本使用開發當下的最新穩定版，並在 `package.json` 鎖定。

**專案結構（建議）**

```
src/
  db/            Dexie schema、migration、repository
  domain/        型別定義、計算公式（純函式，不碰 UI 與 DB）
  features/
    record/      新增場次
    report/      報表
    sessions/    場次列表與詳情
    settings/    設定與資料管理
  components/    共用 UI 元件
  styles/        設計 token
tests/
  unit/          domain 計算測試
  e2e/           Playwright
```

**資料儲存注意事項（必須）**

- App 啟動時呼叫 `navigator.storage.persist()` 申請持久儲存，結果顯示在設定頁。
- iOS 上「加入主畫面」的 App 與 Safari 分頁的儲存空間是分開的。在 Safari 分頁內記的資料，主畫面 App 看不到，反之亦然。設定頁必須顯示目前執行模式（主畫面 App / 瀏覽器分頁），瀏覽器分頁模式下首頁顯示提示條建議加入主畫面。判斷方式：`matchMedia('(display-mode: standalone)')` 或 `navigator.standalone`。
- 沒有雲端備份，資料遺失的唯一補救是 JSON 備份檔（第 8 節）。

**PWA 設定（必須）**

- manifest：`display: standalone`、`start_url: "./#/"`、`scope: "./"`、`lang: "zh-Hant-TW"`，`theme_color` 與 `background_color` 取自深色主題 token。
- 圖示：192×192、512×512（含 maskable 版本）；另提供 180×180 的 `apple-touch-icon`，iOS 主畫面圖示讀的是這個，不是 manifest。
- iOS meta：`apple-mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style: black-translucent`、`apple-mobile-web-app-title`。
- Service worker 預先快取所有建置產物，離線時 App 完整可用。
- App 名稱見 11.3 Q10。

**金額與時間的儲存格式（必須）**

- 金額一律以整數儲存（元），不允許小數；計算中的比率才允許浮點數。
- 時間以裝置本地時間儲存為字串 `YYYY-MM-DDTHH:00`（精度到小時，不含時區）。建立與更新時間戳記錄用 ISO 8601 含時區。
- 時長以整數分鐘儲存。

**開發規範**

- `domain/` 內的計算公式必須是純函式並有單元測試，UI 層不得自行計算指標。
- 所有畫面文字為繁體中文，集中在一個字串檔管理（不需完整 i18n 框架）。
- 依使用者既有工作流程：每個階段開獨立分支，完成後發 MR 由使用者審核。

## 3. 資料模型

三種場次類型存在同一張 `sessions` 表，以 `type` 區分；買入一律以陣列 `buyIns` 儲存，現金桌固定只有 1 筆。賣股份的出資者以陣列 `backers` 嵌入在場次內（3.8），三種類型都適用。場地與盲注級別是獨立的設定表，場次以 id 參照。

### 3.1 Session（場次）

| 欄位 | 型別 | cash | mtt | timed\_mtt | 規則 |
| --- | --- | --- | --- | --- | --- |
| id | string | 必填 | 必填 | 必填 | UUID，系統產生 |
| type | `'cash' \| 'mtt' \| 'timed_mtt'` | 必填 | 必填 | 必填 | 建立後不可變更 |
| startAt | string | 必填 | 必填 | 必填 | `YYYY-MM-DDTHH:00`，本地時間 |
| durationMin | integer | 必填 | 必填 | 必填 | 1–4320（最長 72 小時） |
| buyIns | BuyIn\[\] | 恰 1 筆 | 1–20 筆 | 1–20 筆 | 見 3.2 |
| cashOut | integer | 必填 | 必填 | 必填 | ≥ 0，上限 99,999,999 |
| stakeId | string \| null | 必填 | — | — | 參照 Stake |
| venueId | string \| null | 選填 | 選填 | 選填 | 參照 Venue |
| name | string | 選填 | 選填 | 選填 | 最多 50 字，例：賽事名稱 |
| note | string | 選填 | 選填 | 選填 | 最多 500 字 |
| fieldSize | integer \| null | — | 選填 | — | ≥ 2 |
| finishPlace | integer \| null | — | 選填 | — | 1 ≤ finishPlace ≤ fieldSize |
| backers | Backer\[\] | 選填 | 選填 | 選填 | 0–10 筆；沒有賣股時為空陣列 `[]`，**不得為 null 或省略**；見 3.8（v1.2 新增） |
| createdAt | string | 系統 | 系統 | 系統 | ISO 8601 含時區 |
| updatedAt | string | 系統 | 系統 | 系統 | ISO 8601 含時區 |

「—」表示該類型不使用此欄位，儲存時必須為 `null`。

標準 MTT 填了 finishPlace 就必須同時填 fieldSize；只填 fieldSize 不填 finishPlace 允許。

### 3.2 BuyIn（買入，嵌入在 Session 內）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| amount | integer | 必填，1–99,999,999，**含服務費** |
| fee | integer | 必填，預設 0，0 ≤ fee ≤ amount |

陣列順序即買入順序，第 1 筆是首次進場，其餘為再買入（re-entry）。

### 3.3 Venue（場地）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| id | string | UUID |
| name | string | 必填，1–30 字，去除前後空白後不可與其他場地重複（不分大小寫） |
| archived | boolean | 預設 false |
| sortOrder | integer | 表單選單排序用 |

### 3.4 Stake（盲注級別）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| id | string | UUID |
| sb | integer | 必填，≥ 1 |
| bb | integer | 必填，≥ sb |
| archived | boolean | 預設 false |
| sortOrder | integer | 表單選單排序用 |

顯示名稱由系統產生 `sb/bb`（例：`50/100`），不另存。同一組 sb、bb 不可重複。

### 3.5 Settings（設定，key-value）

| key | 型別 | 用途 |
| --- | --- | --- |
| lastType | string | 新增頁預設選取上次使用的類型 |
| lastVenueByType | Record\<type, venueId> | 各類型預帶上次場地 |
| lastStakeId | string | 現金桌預帶上次盲注 |
| lastBackupAt | string | 上次匯出備份時間，用於備份提醒 |
| recordDraft | object | 新增頁草稿（5.6） |

### 3.6 參照完整性

- 場地與盲注級別**不提供實體刪除**，只能封存（archived）。封存後不出現在新增頁選單，但歷史場次與報表仍正常顯示名稱。
- 尚未被任何場次參照的場地或盲注，可以實體刪除。
- 盲注級別被參照後，sb、bb 不可修改（避免歷史 bb/hr 被竄改）；場地名稱可隨時改名。
- 編輯舊場次時，若其場地或盲注已封存，選單仍顯示該選項並標註「已封存」。

### 3.7 Dexie schema

**version 1（v1.0，P1 已實作，不得修改或刪除此定義）**

```
sessions: 'id, type, startAt, venueId, stakeId'
venues:   'id, name, archived'
stakes:   'id, archived'
settings: 'key'
```

之後任何 schema 變更都必須透過 Dexie 的 `version(n).upgrade()` 遷移，不得清除既有資料。

**version 2（v1.2，賣股份）**

`backers` 不需要索引（不以出資者查詢、篩選或排序；名稱建議在記憶體內從場次計算，5.3），所以 stores 定義與 version 1 完全相同，只新增遷移函式：

```
db.version(1).stores({ ...v1 定義 })          // 保留，不得刪除
db.version(2).stores({
  sessions: 'id, type, startAt, venueId, stakeId',
  venues:   'id, name, archived',
  stakes:   'id, archived',
  settings: 'key',
}).upgrade(tx =>
  tx.table('sessions').toCollection().modify(s => {
    if (!Array.isArray(s.backers)) s.backers = []
  })
)
```

- 必須：遷移只補 `backers: []`，不得改動任何其他欄位（包含 `updatedAt`，遷移不算使用者修改，不得觸發 8.7 備份提醒）。
- 必須：不得刪除、重建資料庫或清空任何表。使用者手機上已有 version 1 的正式資料，升級後所有場次、場地、盲注、設定必須完整保留。
- 必須：遷移失敗時 Dexie 會回滾交易，資料維持 version 1。App 顯示錯誤狀態「資料升級失敗，請關閉 App 後重新開啟；你的資料沒有遺失」，不得進入可寫入的畫面。
- 必須：處理 `versionchange` 事件。同一裝置上舊版頁面仍開著 version 1 連線時，舊頁面收到事件後關閉連線並顯示「有新版本 · 重新載入」（同 8.10 的提示條），避免新版升級被擋住。
- 版本號：`DB_VERSION` 由 1 改為 2；之後 v2 手牌功能使用 version 3（11.2）。

### 3.8 Backer（出資者，嵌入在 Session 內，v1.2）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| name | string | 必填，去除前後空白後 1–20 字；同一場次內不可重複（去除前後空白後比較，不分大小寫） |
| sharePermille | integer | 必填，比例的千分比：1–1000（0.1%–100.0%）。例：125 = 12.5%、300 = 30.0% |
| markupPermille | integer | 必填，加價倍數的千分之一：1000–3000（1.0×–3.0×），預設 1000。例：1000 = 1.0×（不加價）、1150 = 1.15× |

- 三種類型（cash、mtt、timed\_mtt）都適用，規則相同。
- 每場 0–10 位出資者。陣列順序即輸入順序，詳情與 CSV 依此順序顯示。
- 同一場所有出資者的 sharePermille 總和必須 ≤ 1000（賣出合計 ≤ 100%）；等於 1000 表示全部賣出，允許。
- 比例套用在整場所有買入的總額，不逐筆買入設定（4.6）。
- **比例與倍數必須以整數儲存，不得存成浮點數**（例如不得存 `0.125` 或 `1.15`），避免浮點誤差；計算時一律以整數運算（4.6）。
- 不允許折價（倍數 < 1.0×）；上限 3.0× 同時保證 4.6 的整數乘積不超過 `Number.MAX_SAFE_INTEGER`（買入總額上限 20 × 99,999,999 = 1,999,999,980；× 1000 × 3000 ≈ 6.0 × 10¹⁵ < 9.007 × 10¹⁵）。範圍見 11.3 Q11。
- 筆數上限與名稱規則見 11.3 Q12、Q13。
- 不記錄付款或分帳狀態，不記錄出資者 id 或聯絡資訊；出資者沒有獨立的設定表，名稱只存在場次內（11.3 Q7）。
- 名稱儲存去除前後空白後的值。

## 4. 計算規則

所有指標只依買入、到手金額、時長與出資者（backers）計算；服務費已含在買入內，只用於服務費統計，絕不再從盈利扣除。公式一律實作在 `domain/`，每條都要有單元測試。

**口徑（v1.2）**：每個指標屬於「全額」或「份額」其中一種。「全額」以整場的買入總額與 cashOut 計算；「份額」以 4.6 的你的成本、你的到手、你的盈利計算。沒有賣股的場次（`backers` 為空）兩者相等，所以 v1 的所有結果不變。本節表格中的「盈利」若未特別註明，一律指**你的盈利**。

### 4.1 單一場次

```latex
\text{買入總額} = \sum \text{buyIns[i].amount} \qquad \text{服務費總額} = \sum \text{buyIns[i].fee}
```

```latex
\text{全額盈利} = \text{cashOut} - \text{買入總額}
```

- 你的盈利（myProfit）依 4.6 計算；沒有賣股時你的盈利 = 全額盈利。
- 進場次數 = buyIns 筆數。
- 結果判定以**你的盈利**為準：> 0 為「贏」，< 0 為「輸」，= 0 為「平」。「平」不算贏。
- 現金桌單場 bb 盈利 = 你的盈利 ÷ 該場 bb。
- 單場時薪（詳情 7.2）= 你的盈利 ÷（durationMin ÷ 60）。

驗算例：限時 MTT 買入 3,400（服務費 400）+ 3,200（服務費 200），到手 9,000，沒有賣股。買入總額 6,600、服務費總額 600、進場 2 次、全額盈利 = 你的盈利 = +2,400。

### 4.2 彙總指標（對一組場次 S）

| 指標 | 口徑 | 公式 | 分母為 0 時 | 顯示格式 |
| --- | --- | --- | --- | --- |
| 盈利 | 份額 | Σ 你的盈利 | — | `+$1,523` / `−$4,000` / `$0` |
| 場次數 | — | S 的筆數 | — | 整數 |
| 贏率 | 份額 | 贏的場次數（依 4.1，以你的盈利判定）÷ 場次數 | 顯示 `—` | `13/26（50.0%）` |
| 平均每場盈利 | 份額 | Σ 你的盈利 ÷ 場次數 | 顯示 `—` | 金額 |
| 總投入 | 份額 | Σ 你的成本 | — | 金額（可能為負，見 4.6） |
| 總到手 | 份額 | Σ 你的到手 | — | 金額（可能為負，見 4.6） |
| ROI | 份額 | Σ 你的盈利 ÷ Σ 你的成本 | Σ 你的成本 ≤ 0 時顯示 `—` | 百分比，小數 1 位，含正負號 |
| 總時數 | — | Σ durationMin ÷ 60 | — | `123.5 小時` |
| 時薪 | 份額 | Σ 你的盈利 ÷ 總時數 | 顯示 `—` | 金額，後綴 `/hr` |
| 總服務費 | 全額 | Σ 服務費總額 | — | 金額 |
| 服務費比例 | 全額 | Σ 服務費總額 ÷ Σ 買入總額 | 顯示 `—` | 百分比，小數 1 位 |

- 恆等式：總到手 − 總投入 = 盈利（皆為份額），報表上三個數字對得起來。
- ROI 分母為你的成本：全部賣出且不加價時你的成本為 0，全部賣出且加價時可能為負；分母 ≤ 0 時比率沒有意義，一律顯示 `—`。
- 服務費比例的分母是**全額**買入總額，不是畫面上的「總投入」（份額）；服務費反映場地收費，與你賣出多少無關。

### 4.3 類型專屬指標

| 指標 | 適用 | 口徑 | 公式 | 分母為 0 時 | 顯示格式 |
| --- | --- | --- | --- | --- | --- |
| bb/hr | cash | 份額 | Σ（你的盈利ᵢ ÷ bbᵢ）÷ 總時數 | `—` | 小數 1 位，後綴 `bb/hr` |
| ITM% | mtt | 全額 | 到手金額（cashOut，全額）> 0 的場次數 ÷ 場次數 | `—` | `8/40（20.0%）` |
| 平均名次百分位 | mtt | — | 平均（finishPlace ÷ fieldSize），只計兩欄都有填的場次 | `—` | `前 23.5%`，並附註樣本數 `（n=12）` |
| 平均進場次數 | mtt、timed\_mtt | — | Σ 進場次數 ÷ 場次數 | `—` | 小數 2 位 |
| 平均單次買入（ABI） | mtt、timed\_mtt | 全額 | Σ 買入總額 ÷ Σ 進場次數 | `—` | 金額 |

bb/hr 按各場自己的 bb 換算後再加總，混合不同盲注級別也正確。平均名次百分位數字越小越好，例如 100 人打到第 10 名為前 10%。

ITM% 屬於比賽結果（有沒有打進錢圈），全部賣出時你的到手為 0，但只要 cashOut > 0 仍算進錢圈。ABI 反映比賽級別，以整場買入計算，不因賣股而變小。

### 4.4 數值與顯示規則（必須）

- 金額顯示為整數、千分位逗號、`$` 前綴。計算出的平均金額在顯示時才四捨五入，以絕對值進位（−2.5 → −3），避免 `Math.round` 對負數的偏差。
- 百分比與 bb/hr 在顯示時四捨五入，內部計算不得提前捨入。
- 負號使用正式減號 `−`（U+2212）顯示；匯出檔一律用 ASCII `-`。
- 正負顏色見第 9 節，正負號永遠顯示，不只靠顏色區分。
- 比例顯示（v1.2）：sharePermille ÷ 10 加 `%`；整數時不顯示小數（300 → `30%`），否則顯示 1 位（125 → `12.5%`）。合計比例與「你佔」比例同樣規則（例：賣出 `30%` · 你佔 `70%`）。CSV 例外，見 8.6。
- 加價倍數顯示（v1.2）：`×` 前綴，markupPermille ÷ 1000，去除尾端 0 但至少保留 1 位小數（1000 → `×1.0`、1200 → `×1.2`、1150 → `×1.15`、1125 → `×1.125`）。
- 出資者付款、分走獎金在計算當下就捨入為整數（4.6），不適用「顯示時才捨入」；這是本節唯一的例外。

### 4.5 期間篩選

以 startAt 的本地日期判斷，與結束時間無關。

| 選項 | 範圍 |
| --- | --- |
| 全部 | 不限 |
| 近三個月 | 今天往前推 3 個月的當天 00:00 起，到今天結束 |
| 近半年 | 今天往前推 6 個月的當天 00:00 起，到今天結束 |
| 自訂 | 起日 00:00 至迄日 23:59，兩端皆含；起日不可晚於迄日 |

月份加減使用 dayjs `subtract(n, 'month')`，月底日期自動收斂（例：5/31 往前 3 個月為 2/28 或 2/29）。未來日期的場次不會出現，因為表單禁止未來時間（第 5 節）。

### 4.6 賣股份（v1.2）

玩家把這場的部分股份賣給一位或多位出資者：出資者依比例 × 加價倍數付錢給你，結束後依比例分走到手金額。比例套用在**整場所有買入的總額**（含再買入），不逐筆設定。只支援「賣出」；買別人的股份不在範圍內。

**單場公式**（對場次的第 i 位出資者，sᵢ = sharePermille、mᵢ = markupPermille）：

```latex
\text{pay}_i = \operatorname{round}\!\left(\frac{\text{買入總額} \times s_i \times m_i}{1{,}000{,}000}\right)
\qquad
\text{payout}_i = \operatorname{round}\!\left(\frac{\text{cashOut} \times s_i}{1{,}000}\right)
```

```latex
\text{你的成本} = \text{買入總額} - \sum \text{pay}_i
\qquad
\text{你的到手} = \text{cashOut} - \sum \text{payout}_i
```

```latex
\text{你的盈利} = \text{你的到手} - \text{你的成本} = (\text{cashOut} - \sum \text{payout}_i) - \text{買入總額} + \sum \text{pay}_i
```

- payᵢ（出資者付款）：出資者 i 付給你的錢。payoutᵢ（分走獎金）：出資者 i 從到手金額分走的錢。
- 沒有出資者時 Σpay = Σpayout = 0，你的成本 = 買入總額、你的到手 = cashOut、你的盈利 = 全額盈利。
- 賣出比例合計 = Σsᵢ（千分比）；你佔比例 = 1000 − Σsᵢ。
- 服務費總額不分攤，永遠是整場全額。
- 程式命名（建議）：`backerPay(buyInTotal, backer)`、`backerPayout(cashOut, backer)`、`myCost(session)`、`myCashOut(session)`、`myProfit(session)`、`fullProfit(session)`；彙總與 UI 一律呼叫這些純函式，不得自行計算。

**捨入規則（必須）**

- 每位出資者的 payᵢ、payoutᵢ **各自**四捨五入到整數，你的成本、你的到手、你的盈利都用捨入後的金額計算，確保「出資者付款合計 + 你的成本 = 買入總額」與「分走獎金合計 + 你的到手 = cashOut」兩條帳永遠成立。
- 四捨五入以絕對值進位（同 4.4）；此處分子分母都 ≥ 0，即 0.5 一律進位。
- **必須以整數運算**：分子 N = 買入總額 × sᵢ × mᵢ（或 cashOut × sᵢ）、分母 D = 1,000,000（或 1,000），計算 q = ⌊N ÷ D⌋、r = N − q × D，若 2r ≥ D 則結果為 q + 1，否則為 q。不得先把比例換成小數再相乘（例：1,050 × 0.2 × 1.15 以浮點數計算得 241.4999…，`Math.round` 得 241；正確值 241.5 應進位為 242，見 C21）。3.8 的上限保證 N 不超過 `Number.MAX_SAFE_INTEGER`。
- 已知極端情況：多位出資者各自進位，可能使 Σpayᵢ 略大於買入總額 × 賣出比例 × 倍數，或在到手金額極小時 Σpayoutᵢ 大於 cashOut，使你的成本或你的到手出現小額負數（例：cashOut 1、兩位各 50% 時 Σpayout = 2、你的到手 −1）。這是各自捨入的必然結果，照實顯示，不另做修正（12.3）。

**輸贏判定**：以你的盈利判定贏、輸、平（4.1）。全部賣出且不加價時你的盈利通常為 0，判定為平。

**各指標的口徑**：全部列在 4.2、4.3 表格的「口徑」欄。摘要如下，不在此列出的指標不受賣股影響。

| 份額（用你的成本 / 你的到手 / 你的盈利） | 全額（用整場買入總額 / cashOut） |
| --- | --- |
| 盈利、贏率、平均每場盈利、總投入、總到手、ROI（分母為 Σ 你的成本）、時薪、bb/hr、單場 bb 盈利、單場時薪、累積盈利曲線（6.3）、分組統計的盈利 / ROI / 時薪 / bb/hr（6.4）、列表與月份彙總盈利（7.1） | 總服務費、服務費比例（分母為全額買入總額）、ABI、ITM%（以 cashOut > 0 判定） |

**驗算例**（MTT 買入 10,000、服務費 0，賣出 30%：A 比例 10%、B 比例 20%）

| 情境 | Σpay | 你的成本 | Σpayout | 你的到手 | 你的盈利 | 全額盈利 |
| --- | --- | --- | --- | --- | --- | --- |
| 不加價（A、B ×1.0），到手 50,000 | 1,000 + 2,000 = 3,000 | 7,000 | 5,000 + 10,000 = 15,000 | 35,000 | +28,000 | +40,000 |
| 加價（A、B ×1.2），到手 50,000 | 1,200 + 2,400 = 3,600 | 6,400 | 15,000 | 35,000 | +28,600 | +40,000 |
| 不加價，到手 0 | 3,000 | 7,000 | 0 | 0 | −7,000 | −10,000 |
| 加價 ×1.2，到手 0 | 3,600 | 6,400 | 0 | 0 | −6,400 | −10,000 |

以第一列驗算：你的盈利 = (50,000 − 15,000) − 10,000 + 3,000 = +28,000；你佔 70%，全額盈利 40,000 × 70% = 28,000，兩者一致。加價時多收的 600（3,600 − 3,000）直接成為你的盈利。

## 5. 功能：新增場次

新增頁是 App 首頁，目標是最常見的一筆紀錄在 30 秒內完成。表單頂端選類型，欄位隨類型切換；常用值（類型、場地、盲注、日期）自動帶入。

### 5.1 類型選擇

- 分段選擇器三個選項：現金桌 / MTT / 限時 MTT。
- 預設選取 Settings.lastType；首次使用預設現金桌。
- 切換類型時，共用欄位的已填值保留，類型專屬欄位清空。賣股份（出資者列）屬共用欄位，切換類型時保留。
- 從 MTT 或限時 MTT 切到現金桌時，若買入超過 1 筆，跳出確認視窗「現金桌只有一筆買入，切換後只保留第一筆，確定嗎？」，取消則不切換。

### 5.2 欄位順序

| 順序 | 現金桌 | MTT | 限時 MTT |
| --- | --- | --- | --- |
| 1 | 盲注級別 | 買入列表 | 買入列表 |
| 2 | 買入 + 服務費 | 到手金額 | 到手金額 |
| 3 | 到手金額 | 賣股份（v1.2） | 賣股份（v1.2） |
| 4 | 賣股份（v1.2） | 參賽人數、名次（同一列） | 開始時間 |
| 5 | 開始時間 | 開始時間 | 時長 |
| 6 | 時長 | 時長 | 場地 |
| 7 | 場地 | 場地 | 名稱 |

| 9 | 備註 | 備註 | — |

賣股份緊接在到手金額之後，讓所有金額相關欄位集中在一起。

表單底部固定即時預覽：

- 沒有出資者列時一行，與 v1.1 相同：「買入 $6,600（2 次）· 服務費 $600 · 盈利 +$2,400」。買入與到手金額都有有效值才顯示盈利，否則顯示 `—`。
- 有任何出資者列時改為兩行：
  - 第一行：「買入 $10,000（1 次）· 服務費 $0 · 全額 +$40,000」（全額盈利，條件同上）。
  - 第二行：「賣出 30% · 你的盈利 +$28,000」。賣出比例取所有比例欄有效值的合計；你的盈利需買入、到手金額與每一列的比例、倍數都有效（不含名稱）才顯示，否則顯示 `你的盈利 —`。
  - 預覽列兩行時高度增加，仍須符合 9.2「正在輸入的欄位不得被遮住」。

### 5.3 欄位行為

**買入列表（MTT、限時 MTT）**

- 預設一列，每列兩個輸入框：買入（含服務費）、服務費。標題寫明「買入（含服務費）」，避免誤填。
- 列表下方「＋ 再買入」按鈕新增一列，新列預填上一列的買入與服務費，可直接修改。
- 第 2 列起每列右側有刪除鈕；只剩 1 列時不顯示刪除鈕。
- 上限 20 列，達上限後按鈕停用。
- 列前標示序號「第 1 次」「第 2 次」。

**現金桌買入**：單一一組買入 + 服務費，沒有再買入按鈕。買入填整場總投入。

**服務費**：預設 0，可留空（留空視為 0）。輸入框旁小字說明「已含在買入內，僅記錄」。

**金額輸入框（所有金額共用）**

- `inputmode="numeric"`，iPhone 叫出數字鍵盤。
- 只接受數字，貼上含逗號或 `$` 的文字時自動移除非數字字元。
- 輸入中即時加千分位逗號顯示。
- 字級至少 16px，避免 iOS Safari 聚焦時自動放大畫面。

**盲注級別（現金桌）**

- 下拉選單列出未封存的盲注，依 sortOrder 排序，預設帶入 Settings.lastStakeId。
- 選單最後一項「＋ 新增盲注」，打開小視窗輸入 sb、bb，儲存後自動選取。
- 尚無任何盲注時，選單顯示「請先新增盲注」並直接開啟新增視窗。

**場地**：行為同盲注選單，含「＋ 新增場地」與「不指定」選項；依類型預帶 Settings.lastVenueByType。

**開始時間**：日期選擇器（年/月/日）+ 小時選單（0–23 時）。預設今天、目前的小時。顯示格式 `2026/09/27 20 時`。

**時長**：小時選單（0–72）+ 分鐘選單（0–55，每 5 分鐘一格）。無預設值，必填。儲存為總分鐘數。

**參賽人數、名次（MTT）**：同一列兩個數字輸入框，顯示為「第 \[ \] 名 / 共 \[ \] 人」。

**賣股份（三種類型，v1.2）**

- 預設收合：沒有出資者列時只顯示一列區塊標題「賣股份」與「＋ 賣股份」按鈕，旁邊小字「沒有賣股可略過」。
- 按「＋ 賣股份」新增第 1 列並展開；展開後按鈕文字改為「＋ 新增出資者」，放在列表下方。刪除到 0 列時回到收合狀態。
- 展開時標題列右側顯示摘要「已賣 30% · 你佔 70%」（依比例欄有效值的合計，比例格式見 4.4）。
- 上限 10 列，達上限後「＋ 新增出資者」停用。
- 每列內容：
  - 第一行：出資者名稱（文字輸入框，placeholder「出資者名稱」），右側刪除鈕（每一列都有，含第 1 列；`aria-label`「刪除出資者」）。
  - 第二行：比例（輸入框 + 後綴 `%`）、加價倍數（前綴 `×` + 輸入框）。
  - 第三行小字：「付你 $1,000 · 分走 $5,000」，依 4.6 即時計算；買入無效時付款顯示 `—`，到手金額無效時分走顯示 `—`；該列比例或倍數無效時兩者都顯示 `—`。
- 新增的列：名稱與比例空白，加價倍數預填 `1.0`。
- 比例輸入框：`inputmode="decimal"`；只接受數字與一個小數點，貼上時移除 `%`、空白與其他非數字字元；範圍 0.1–100，最多 1 位小數。
- 加價倍數輸入框：`inputmode="decimal"`；只接受數字與一個小數點，貼上時移除 `×`、`x`、`X` 與其他非數字字元；範圍 1.0–3.0，最多 3 位小數。
- 字串轉成儲存值必須精確：比例「12.5」→ sharePermille 125、倍數「1.15」→ markupPermille 1150。建議以字串拆整數與小數部分再組成整數，不得以浮點數相乘後無條件截斷。
- 輸入框字級至少 16px（同金額輸入框）。

**出資者名稱建議**

- 名稱輸入框聚焦或輸入時，在輸入框下方顯示建議清單（自製下拉，不使用 `<datalist>`，iOS Safari 支援不一致）。
- 來源：所有已儲存場次的 `backers[].name`。編輯模式不排除目前這一場自己的紀錄。
- 去重：去除前後空白後不分大小寫視為同一名稱，保留最近一次使用時的寫法。
- 排序：依最近使用排序，即該名稱出現過的場次中最新的 startAt 由新到舊，同時間依 createdAt 由新到舊。
- 篩選：輸入框有文字時只列出包含該文字的名稱（部分符合、不分大小寫）；空白時列出全部。排除目前表單其他列已填的名稱（同樣去空白、不分大小寫比較）。
- 最多顯示 8 筆；點選後填入名稱並收起清單。沒有符合的名稱時不顯示清單。
- 不另設出資者管理頁；名稱只能在場次內修改，修改某場的名稱不影響其他場次。

### 5.4 驗證規則

驗證在按下儲存時執行；已顯示錯誤的欄位，修改後即時重新驗證。儲存按鈕不停用，失敗時捲動到第一個錯誤欄位。

| 規則 | 錯誤訊息 |
| --- | --- |
| 現金桌未選盲注 | 請選擇盲注級別 |
| 買入空白或為 0 | 請填寫買入金額 |
| 服務費 > 該筆買入 | 服務費不可大於買入 |
| 到手金額空白 | 請填寫到手金額，沒拿回請填 0 |
| 任一金額超過 99,999,999 | 金額超出上限 |
| 時長為 0 小時 0 分，或超過 72 小時 | 請選擇 5 分鐘到 72 小時之間的時長 |
| 開始時間晚於現在（依小時比較） | 開始時間不可是未來 |
| 參賽人數 < 2 | 參賽人數至少 2 人 |
| 填了名次未填參賽人數 | 填名次時請一併填寫參賽人數 |
| 名次 > 參賽人數或名次 < 1 | 名次需介於 1 到參賽人數之間 |
| 名稱超過 50 字、備註超過 500 字 | 字數超過上限（輸入框附字數計數） |
| 出資者名稱空白 | 請填寫出資者名稱 |
| 出資者名稱去除前後空白後超過 20 字 | 出資者名稱最多 20 字 |
| 同一場出資者名稱重複（去除前後空白、不分大小寫） | 出資者名稱重複 |
| 出資者比例空白或為 0 | 請填寫比例 |
| 出資者比例不是數字或超過 1 位小數 | 比例最多到小數 1 位 |
| 出資者比例大於 100 | 比例需介於 0.1% 到 100% 之間 |
| 所有出資者比例合計超過 100%（錯誤顯示在賣股份區塊標題下方） | 賣出比例合計不可超過 100%（目前 105%） |
| 加價倍數空白 | 請填寫加價倍數 |
| 加價倍數不是數字或超過 3 位小數 | 加價倍數最多到小數 3 位 |
| 加價倍數小於 1.0 或大於 3.0 | 加價倍數需介於 1.0 到 3.0 之間 |

出資者列的補充規則：

- 名稱與比例都空白、且倍數空白或等於 1.0 的列視為空白列，儲存時自動移除，不套用上表任何規則，不報錯（例如按了「＋ 新增出資者」但沒有填）。上表出資者規則只套用在非空白列。
- 合計錯誤訊息中的「目前 105%」依 4.4 比例格式顯示目前合計。合計恰為 100% 合法（全部賣出）。
- 已有錯誤的出資者欄位修改後即時重新驗證；合計錯誤在任一比例欄修改後即時重新驗證。

### 5.5 儲存後行為

- 寫入 DB 成功後顯示提示「已儲存，盈利 +$2,400」，停留在新增頁。有出資者時改為「已儲存，你的盈利 +$28,000」（你的盈利，4.6）。
- 更新 Settings：lastType、lastVenueByType、lastStakeId。出資者不存入任何 last\* 設定。
- 表單重置：類型、場地、盲注、日期保留；金額、時長、名稱、備註、參賽人數、名次清空；買入列表回到 1 列；出資者列全部清空，賣股份區塊回到收合。
- 寫入失敗：顯示「儲存失敗，請再試一次」，表單內容不清空。
- 防重複送出：儲存處理中按鈕停用並顯示載入狀態。

### 5.6 草稿

表單有任何輸入時，內容自動存入 Settings.recordDraft（輸入停止 500ms 後寫入）。App 被系統關閉或切換分頁後回到新增頁，自動還原草稿。儲存成功或按下表單右上角「清除」後刪除草稿。

草稿包含出資者列（每列的名稱、比例、倍數，以使用者輸入的原始字串保存，含尚未通過驗證的值與空白列），還原後列數、內容與展開狀態與離開前相同。v1.1 版本存下、沒有出資者資料的草稿，還原時視為 0 列。

### 5.7 編輯模式

從場次詳情進入編輯時沿用同一個表單元件，差異如下：

- 標題為「編輯場次」，帶入該場次全部欄位，包含出資者列（依儲存順序；有出資者時賣股份區塊展開）。出資者可修改、新增、刪除，規則同新增模式。
- 類型選擇器停用，下方小字「類型無法修改，如需更改請刪除後重新新增」。
- 不讀寫草稿、不更新 last\* 設定。
- 儲存後更新 updatedAt，返回場次詳情。
- 有未儲存變更時按返回，跳出「放棄變更？」確認。出資者列的增刪與修改算作變更。
- 「開始時間不可是未來」規則同樣適用。

## 6. 功能：報表

報表頁由上到下為：分類頁籤、期間篩選、指標卡、累積盈利曲線、分組統計。切換頁籤或期間時，下方所有區塊同步重算。公式一律來自第 4 節。

**賣股份的口徑（v1.2）**：報表所有盈利類數字（盈利、贏率、平均每場盈利、總投入、總到手、ROI、時薪、bb/hr、曲線、分組的盈利 / ROI / 時薪 / bb/hr）一律用你的份額；總服務費、服務費比例、ABI、ITM% 用全額。各指標口徑以 4.2、4.3 表格為準。報表**不提供**全額 / 份額切換。目前頁籤與期間的場次中有任何一場有出資者時，指標卡下方顯示一行小字「含賣股場次，盈利相關指標以你的份額計算」；沒有時不顯示。

### 6.1 分類頁籤與期間

- 頁籤：總體 / 現金桌 / MTT / 限時 MTT，預設總體。
- 期間：全部 / 近半年 / 近三個月 / 自訂，預設全部。選自訂時展開起迄日期選擇器。
- 頁籤與期間的選擇在 App 開啟期間保留，切到其他頁面再回來不重置；App 重啟後回到預設。

### 6.2 各頁籤指標

指標卡以雙欄格狀排列，第一張「盈利」橫跨整列並加大字級。表中 ✓ 為該頁籤顯示的指標，呈現順序即表格由上到下。

| 指標 | 總體 | 現金桌 | MTT | 限時 MTT |
| --- | --- | --- | --- | --- |
| 盈利 | ✓ | ✓ | ✓ | ✓ |
| 場次數 | ✓ | ✓ | ✓ | ✓ |
| 贏率 | ✓ | ✓ | ✓ | ✓ |
| ROI |  |  | ✓ | ✓ |
| 時薪 |  | ✓ | ✓ | ✓ |
| bb/hr |  | ✓ |  |  |
| ITM% |  |  | ✓ |  |
| 平均名次百分位 |  |  | ✓ |  |
| 平均每場盈利 |  | ✓ | ✓ | ✓ |
| ABI |  |  | ✓ | ✓ |
| 平均進場次數 |  |  | ✓ | ✓ |
| 總時數 | ✓ | ✓ | ✓ | ✓ |
| 總投入 | ✓ | ✓ | ✓ | ✓ |
| 總到手 | ✓ | ✓ | ✓ | ✓ |
| 總服務費 | ✓ | ✓ | ✓ | ✓ |
| 服務費比例 | ✓ | ✓ | ✓ | ✓ |

- 總體頁不顯示 ROI、時薪等比率型指標，因為現金桌與錦標賽混算會失真。贏率是例外，沿用參考畫面的習慣。
- 現金桌不顯示 ROI：現金桌買入金額隨個人習慣浮動（可以買 100bb 也可以買 300bb），ROI 沒有參考價值，改看時薪與 bb/hr。
- 總體頁指標卡下方加一個小表：三種類型各自的場次數與盈利（你的盈利），點擊整列跳到該類型頁籤。
- 指標卡名稱不因賣股而改變（仍為「盈利」「總投入」等），口徑以上方說明與 4.2、4.3 為準。

### 6.3 累積盈利曲線

- 折線圖，X 軸為場次序號（依 startAt 由舊到新，同時間再依 createdAt），Y 軸為累積盈利（累積你的盈利，4.6）。以場次序號而非日期為 X 軸，避免密集打牌的日子擠成一點。
- 資料與當前頁籤、期間一致；期間篩選時從 0 開始累積。
- Y = 0 畫一條虛線基準線。
- 手指點按或滑過曲線時顯示：日期、類型、該場盈利（你的盈利）、累積盈利。該場有出資者時，該場盈利後加註「（賣 30%）」，比例格式見 4.4。
- 符合條件的場次少於 2 筆時，圖表區顯示「至少需要 2 場紀錄才能畫出曲線」。
- 超過 500 點時不繪製個別資料點圓圈，只畫線，維持流暢。

### 6.4 分組統計

分組依據以分段選擇器切換，可選項目依頁籤而定：

| 頁籤 | 可選分組 | 各組顯示欄位 |
| --- | --- | --- |
| 總體 | 場地 | 場次數、盈利、總服務費 |
| 現金桌 | 場地、盲注級別 | 場次數、盈利、時薪、bb/hr |
| MTT | 場地、名稱 | 場次數、盈利、ROI、ITM% |
| 限時 MTT | 場地、名稱 | 場次數、盈利、ROI、時薪 |

- 各組欄位口徑：盈利、ROI、時薪、bb/hr 用份額；總服務費、ITM% 用全額（4.2、4.3）。分組依據與欄位不因賣股而增減；不提供依出資者分組（11.3 Q17）。
- 各組依盈利（你的盈利）由高到低排序。
- 未指定場地的場次歸到「未指定」組，永遠排最後；未填名稱的歸到「未命名」組，同樣排最後。
- 名稱分組以去除前後空白後完全相同為同一組（大小寫不分）。
- 已封存的場地與盲注照常列入統計。
- 點擊某一組，跳到場次列表並套用同樣的類型、期間與該分組篩選。

### 6.5 空狀態

- 完全沒有紀錄：整頁顯示「還沒有紀錄」與「去新增第一場」按鈕。
- 有紀錄但目前頁籤與期間沒有符合的：指標卡顯示 `—`，圖表與分組區顯示「這個期間沒有紀錄」。

### 6.6 效能

以 5,000 筆場次測試，切換頁籤或期間後到畫面更新完成需在 300ms 內（iPhone 實機）。計算在記憶體內進行，必要時以 memo 快取。

## 7. 功能：場次列表與詳情

紀錄頁列出所有場次，依月份分組、新的在前；點進單筆可檢視完整內容、編輯、複製、刪除。

### 7.1 列表

**排序與分組**：依 startAt 由新到舊，同時間依 createdAt 由新到舊。以月份為分組標題，標題列顯示「2026 年 9 月 · 8 場 · +$12,300」（盈利為 Σ 你的盈利），標題列捲動時黏在頂端。

**單列內容**（左到右）：類型圖示、日期 `09/27`、標題、盈利（你的盈利，含正負號與顏色）、箭頭。標題依序取第一個有值的：

1. name
2. 現金桌：`場地 · 50/100`；錦標賽：場地名稱
3. 現金桌：`50/100`；錦標賽：類型名稱（MTT / 限時 MTT）

錦標賽進場 2 次以上時，標題後加小標籤 `×2`。

有出資者的場次（三種類型），標題後加小標籤 `賣30%`（賣出比例合計，格式見 4.4；與 `×2` 同時存在時排在 `×2` 之後），提示該列盈利是你的份額。標題過長時標題文字省略，標籤不省略。

**篩選**

- 類型：全部 / 現金桌 / MTT / 限時 MTT。
- 期間：與報表相同的四個選項與規則（第 4.5 節）。
- 關鍵字：比對 name 與 note，不分大小寫、部分符合。不比對出資者名稱（11.3 Q17）。
- 從報表分組跳過來時，額外套用場地、盲注或名稱篩選，以可移除的標籤顯示在篩選列（例：`場地：6bet ✕`）。
- 篩選後月份標題的場次數與盈利，只計算符合篩選的場次。
- 列表頂端顯示篩選結果彙總：「共 26 場 · +$39,600」（Σ 你的盈利）。

**效能**：使用虛擬捲動或分批載入（每批 100 筆），5,000 筆時捲動不卡頓。

**空狀態**：無紀錄時同報表空狀態；篩選無結果時顯示「沒有符合條件的紀錄」與「清除篩選」按鈕。

### 7.2 詳情

顯示內容：

- 頂部：盈利（大字，你的盈利）、類型、標題。有出資者時大字標籤為「你的盈利」，下方小字「全額 +$40,000 · 賣出 30%」。
- 基本資料：開始時間、時長（`4 小時 30 分`）、場地、名稱、現金桌盲注。
- 金額：每筆買入明細（第 1 次 $3,400，服務費 $400）、買入總額、服務費總額、到手金額（皆為全額）。
- 賣股份（只在有出資者時顯示此區塊，v1.2）：
  - 每位出資者一列，依儲存順序：名稱、比例、加價倍數、付你（payᵢ）、分走（payoutᵢ）。例：「A · 10% · ×1.2　付你 $1,200 · 分走 $5,000」。
  - 合計列：賣出 30% · 出資者付款合計 $3,600 · 分走獎金合計 $15,000。
  - 全額結果：買入總額 $10,000、到手金額 $50,000、全額盈利 +$40,000。
  - 你的份額（你佔 70%）：你的成本 $6,400、你的到手 $35,000、你的盈利 +$28,600。
  - 數字一律來自 4.6 的純函式，與列表、報表、CSV 一致。
- 該場衍生數字：時薪；現金桌加 bb 盈利；MTT 有填名次時加「第 12 名 / 180 人（前 6.7%）」。時薪與 bb 盈利以你的盈利計算（4.1）；有出資者時標籤改為「你的時薪」「你的 bb 盈利」。
- 備註全文（保留換行）。
- 底部小字：建立時間、最後修改時間。
- 場地或盲注已封存時，名稱後標註「（已封存）」。

操作按鈕：編輯、複製為新紀錄、刪除。

### 7.3 編輯

見第 5.7 節。

### 7.4 複製為新紀錄

適合常打的固定賽事。按下後切到新增頁，表單預填類型、場地、盲注、名稱、全部買入列、全部出資者列（名稱、比例、倍數，賣股份區塊展開，讓使用者看得到並可修改或刪除；11.3 Q16）；開始時間設為現在，到手金額、時長、參賽人數、名次、備註留空。若新增頁已有草稿，先跳出「覆蓋目前的草稿？」確認。來源場次的場地或盲注已封存時，該欄留空不預填。

### 7.5 刪除

- 按下刪除跳出確認視窗，內容包含該場日期、標題、盈利（你的盈利；有出資者時加註「賣 30%」）。
- 確認後從 DB 實體刪除，返回列表，底部顯示「已刪除 · 復原」提示 5 秒。
- 按復原時，以原始 id、createdAt、updatedAt 原封不動寫回。
- 不提供多選批次刪除。

## 8. 功能：設定與資料管理

設定頁負責常用清單、顯示偏好、備份還原與匯出。因為沒有雲端，備份是防止資料遺失的唯一手段，備份流程必須在 iPhone 主畫面模式實測可用。

### 8.1 場地管理

- 列表顯示名稱與使用場次數，封存項目收在「已封存」折疊區。
- 操作：新增、改名、調整順序（上移/下移按鈕即可，不要求拖拉）、封存、取消封存。
- 使用場次數為 0 時才顯示「刪除」；大於 0 時只能封存。
- 名稱規則見 3.3。

### 8.2 盲注級別管理

- 列表顯示 `sb/bb` 與使用場次數，封存項目收在折疊區。
- 操作：新增、調整順序、封存、取消封存。
- 使用場次數為 0 時可修改 sb、bb 與刪除；大於 0 時兩者都不提供。
- 首次啟動不預載任何盲注，由使用者自行建立。

### 8.3 顯示設定

- 盈虧顏色：「紅色為贏、綠色為輸」（預設，與參考 App 及台股習慣一致）/「綠色為贏、紅色為輸」。存入 Settings.profitColorScheme。
- 深淺色主題跟隨系統，不提供手動切換。

### 8.4 匯出備份（JSON）

檔案格式：

```
{
  "app": "poker-tracker",
  "schemaVersion": 2,
  "exportedAt": "2026-10-01T21:05:00+08:00",
  "sessions": [...],
  "venues": [...],
  "stakes": [...],
  "settings": {...}
}
```

- schemaVersion（v1.2 起為 2）：備份檔格式版本。v1.0–v1.1 匯出的檔案為 1；v1.2 起匯出為 2。
- sessions 每筆的欄位與 3.1 完全一致，必須包含 `backers` 陣列（沒有賣股時為 `[]`），每個元素為 `{ "name": "A", "sharePermille": 100, "markupPermille": 1200 }`（3.8）。
- settings 不包含 recordDraft 與 lastBackupAt。
- 檔名 `poker-backup-YYYYMMDD-HHmm.json`。
- 匯出方式：先判斷 `navigator.canShare({ files })`，可用就開啟 iOS 分享選單（使用者可存到「檔案」或傳到其他 App）；不可用時改用 Blob 下載連結。主畫面模式下的 Blob 下載不穩定，所以分享選單是主要路徑。
- 匯出成功（分享完成或下載觸發）後更新 Settings.lastBackupAt。使用者在分享選單按取消時不更新。

### 8.5 匯入備份（JSON）

- 以檔案選擇器選 `.json` 檔。
- 檢查順序：可解析為 JSON → `app` 為 `poker-tracker` → schemaVersion 不大於目前版本 → 每筆資料通過 Zod 驗證（與第 3 節規則一致）→ 參照的 venueId、stakeId 都存在。任一步失敗就停止，顯示失敗原因與第一筆有問題的資料位置。
- schemaVersion 小於目前版本時，先執行資料遷移再進行 Zod 驗證與匯入。目前版本為 2，定義的遷移如下：
  - 1 → 2：每筆 session 設定 `backers: []`（v1 備份檔沒有此欄位；即使檔案中意外出現 `backers` 也一律覆寫為 `[]`），其他欄位不變。
- schemaVersion 為 2 時，每筆 session 的 `backers` 必須存在且通過 3.8 的規則（名稱 1–20 字且同場不重複、sharePermille 為 1–1000 的整數且合計 ≤ 1000、markupPermille 為 1000–3000 的整數、0–10 筆）；缺少 `backers` 或不符規則即視為驗證失敗，顯示第一筆有問題的資料位置（例：「第 12 筆場次的出資者第 2 位：比例格式錯誤」）。
- 驗證通過後跳出確認視窗，並排顯示「目前：N 場 / 備份檔：M 場（備份時間）」，警告「匯入會取代目前所有資料，建議先匯出備份」。
- 匯入為**完整取代**，不做合併。清除與寫入在同一個 Dexie transaction 內完成，任何錯誤就整個還原，不留下半套資料。
- 匯入完成後清除 recordDraft、將 lastBackupAt 設為備份檔的 exportedAt，顯示「已匯入 M 場紀錄」。

### 8.6 匯出 CSV

- 匯出全部場次，一場一列，依 startAt 由舊到新。
- 欄位（依序，v1.2）：日期、開始時、類型、場地、盲注、名稱、進場次數、買入總額、服務費總額、到手金額、全額盈利、賣出比例、出資者付款總額、分走獎金總額、你的盈利、出資者、時長（分）、參賽人數、名次、備註。
- v1.2 欄位變更：原「盈利」欄改名為「全額盈利」（值不變，= 到手金額 − 買入總額），並在其後新增 5 欄：
  - 賣出比例：Σ sharePermille ÷ 10，固定 1 位小數、不含 `%`（例：`30.0`、`12.5`；沒有賣股為 `0.0`）。
  - 出資者付款總額：Σ payᵢ（4.6），純數字；沒有賣股為 `0`。
  - 分走獎金總額：Σ payoutᵢ（4.6），純數字；沒有賣股為 `0`。
  - 你的盈利：4.6 的你的盈利，純數字；沒有賣股時等於全額盈利。
  - 出資者：文字欄，依儲存順序列出每位出資者 `名稱 比例%×倍數`，以全形分號 `；` 連接，比例與倍數格式同 4.4（例：`A 10%×1.2；B 20%×1.0`）；沒有賣股為空字串。屬文字欄位，適用下方公式注入規則。
- 「你的盈利」= 到手金額 − 分走獎金總額 − 買入總額 + 出資者付款總額，每列都必須成立（可作為匯出測試的檢查式）。
- 編碼 UTF-8 加 BOM，讓 Excel 正確顯示中文；逗號、雙引號、換行依 RFC 4180 跳脫。
- 金額為純數字，無千分位、無 `$`；負數用 ASCII `-`。
- 為防 Excel 公式注入，文字欄位以 `=`、`+`、`-`、`@` 開頭時前面加單引號 `'`。
- 檔名 `poker-sessions-YYYYMMDD.csv`，匯出方式同 8.4。

## 9. UI/UX 規範與推薦 Skills

設計方向是「牌桌旁單手快速記帳」的工具型 App：深色優先、數字清楚、按鈕夠大。此節規則優先於任何設計 skill 的建議，兩者衝突時以本節為準。

### 9.1 導覽與畫面清單

底部固定分頁列四個頁籤：新增 / 紀錄 / 報表 / 設定，預設進入新增。

### 9.2 版面與操作

- 基準寬度 390px，在 375–430px 間不得出現橫向捲動；大於 480px 時內容置中、最大寬度 480px。
- 使用 `viewport-fit=cover`，頂部與底部以 `env(safe-area-inset-*)` 避開瀏海與 Home 指示條。
- 所有可點擊元件的觸控區域至少 44×44px。
- 新增頁的儲存按鈕與盈利預覽列固定在分頁列上方，不隨表單捲動；iOS 鍵盤彈出時，正在輸入的欄位不得被按鈕列或鍵盤遮住。
- 確認視窗、小視窗用底部彈出面板（bottom sheet），危險操作的確認鈕以紅色標示。
- 提示訊息（已儲存、已刪除）顯示在分頁列上方，不遮擋儲存鈕。

### 9.3 視覺

- 深淺色雙主題跟隨系統，設計時以深色為主（牌室燈光偏暗）。顏色一律用 CSS 變數 token 定義在 `styles/`，元件內不得寫死色碼。
- 盈虧顏色以語意 token `--color-gain`、`--color-loss` 呼叫，由 Settings.profitColorScheme 決定對應紅或綠。深淺兩主題下文字對比度至少 WCAG AA（4.5:1）。
- 字型使用系統字型堆疊（iOS 為 PingFang TC），不載入網路字型，確保離線正常。所有金額與數字使用 `font-variant-numeric: tabular-nums`，上下對齊。
- 圖示使用 lucide-react；三種類型各有固定圖示，全 App 一致。
- 動效只用於狀態變化（頁面推入、面板彈出、提示出現），時長 ≤ 250ms；尊重 `prefers-reduced-motion`。
- 這是個人工具，不需要行銷頁式的裝飾。無漸層背景、無牌桌照片背景，讓數字是畫面主角。

### 9.4 狀態與無障礙

- 每個資料畫面必須有三種狀態：載入中、空、錯誤。
- 表單每個欄位有可見標籤（不只用 placeholder），錯誤訊息顯示在欄位下方並以 `aria-describedby` 關聯。
- 盈虧不只靠顏色：永遠帶正負號。
- 所有操作按鈕使用原生 `<button>`，圖示鈕加 `aria-label`。
