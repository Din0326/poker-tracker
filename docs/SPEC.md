## 1. 產品概述

這是一個自用的德州撲克記帳 App，讓使用者在每場牌局結束後 30 秒內記完一筆，並分類看清楚自己在現金桌、標準 MTT、限時 MTT 的長期表現。形式為 PWA，以 iPhone Safari「加入主畫面」為主要使用方式。

**使用者**：單一使用者（開發者本人），無帳號、無登入、無多人功能。

**目標裝置**

| 裝置 | 優先級 | 說明 |
| --- | --- | --- |
| iPhone Safari（加入主畫面） | 必須 | 主要使用情境，所有畫面以 375–430px 寬度設計 |
| 桌機 Chrome（Windows） | 必須可用 | 開發與備份操作用，版面置中、最大寬度 480px 即可 |
| Android Chrome | 不保證 | 不刻意測試 |

**v1 範圍**

- 新增場次：現金桌、標準 MTT、限時 MTT 三種類型，錦標賽支援同場多筆買入
- 報表：分類頁籤、期間篩選、各類指標、累積盈利曲線、分組統計
- 場次列表：檢視、編輯、刪除
- 設定：常用場地與盲注級別管理、JSON 備份還原、CSV 匯出
- PWA：可安裝、離線可用

**非範圍（v1 不做）**

- 手牌紀錄（v2）
- 帳號、登入、雲端同步、多裝置共用
- 多幣別：所有金額視為同一幣別（新台幣），不做幣別欄位與換算
- 推播通知、原生 App 打包
- 線上撲克平台手牌檔匯入

## 2. 技術架構

純前端靜態 PWA，資料全部存在裝置本地 IndexedDB，沒有後端。部署到任一支援 HTTPS 的靜態託管即可。

**技術棧**

| 項目 | 選用 | 等級 | 理由 |
| --- | --- | --- | --- |
| 建置工具 | Vite | 必須 | 輕量、PWA 外掛成熟 |
| 框架 | React + TypeScript（strict） | 必須 | 型別保護計算邏輯 |
| 樣式 | Tailwind CSS | 建議 | 搭配第 9 節設計 token |
| 本地資料庫 | Dexie.js（IndexedDB） | 必須 | 支援 schema 版本遷移與索引查詢 |
| 表單 | React Hook Form + Zod | 建議 | 驗證規則集中定義 |
| 圖表 | Recharts | 建議 | 累積曲線足夠用 |
| 日期 | dayjs | 建議 | 體積小 |
| 路由 | React Router（HashRouter） | 建議 | 靜態託管不需設定 fallback |
| PWA | vite-plugin-pwa（Workbox） | 必須 | 產生 manifest 與 service worker |
| 單元測試 | Vitest | 必須 | 覆蓋第 4 節所有公式 |
| E2E 測試 | Playwright（WebKit + iPhone viewport） | 必須 | 模擬主要使用裝置 |

套件版本使用開發當下的最新穩定版，並在 `package.json` 鎖定。

**專案結構（建議）**

```
src/
  db/            Dexie schema、migration、repository
  domain/        型別定義、計算公式（純函式，不碰 UI 與 DB）
  features/
    record/      新增場次
    report/      報表
    sessions/    場次列表與詳情
    settings/    設定與資料管理
  components/    共用 UI 元件
  styles/        設計 token
tests/
  unit/          domain 計算測試
  e2e/           Playwright
```

**資料儲存注意事項（必須）**

- App 啟動時呼叫 `navigator.storage.persist()` 申請持久儲存，結果顯示在設定頁。
- iOS 上「加入主畫面」的 App 與 Safari 分頁的儲存空間是分開的。在 Safari 分頁內記的資料，主畫面 App 看不到，反之亦然。設定頁必須顯示目前執行模式（主畫面 App / 瀏覽器分頁），瀏覽器分頁模式下首頁顯示提示條建議加入主畫面。判斷方式：`matchMedia('(display-mode: standalone)')` 或 `navigator.standalone`。
- 沒有雲端備份，資料遺失的唯一補救是 JSON 備份檔（第 8 節）。

**PWA 設定（必須）**

- manifest：`display: standalone`、`start_url: "./#/"`、`scope: "./"`、`lang: "zh-Hant-TW"`，`theme_color` 與 `background_color` 取自深色主題 token。
- 圖示：192×192、512×512（含 maskable 版本）；另提供 180×180 的 `apple-touch-icon`，iOS 主畫面圖示讀的是這個，不是 manifest。
- iOS meta：`apple-mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style: black-translucent`、`apple-mobile-web-app-title`。
- Service worker 預先快取所有建置產物，離線時 App 完整可用。
- App 名稱見 11.3 Q10。

**金額與時間的儲存格式（必須）**

- 金額一律以整數儲存（元），不允許小數；計算中的比率才允許浮點數。
- 時間以裝置本地時間儲存為字串 `YYYY-MM-DDTHH:00`（精度到小時，不含時區）。建立與更新時間戳記錄用 ISO 8601 含時區。
- 時長以整數分鐘儲存。

**開發規範**

- `domain/` 內的計算公式必須是純函式並有單元測試，UI 層不得自行計算指標。
- 所有畫面文字為繁體中文，集中在一個字串檔管理（不需完整 i18n 框架）。
- 依使用者既有工作流程：每個階段開獨立分支，完成後發 MR 由使用者審核。

## 3. 資料模型

三種場次類型存在同一張 `sessions` 表，以 `type` 區分；買入一律以陣列 `buyIns` 儲存，現金桌固定只有 1 筆。場地與盲注級別是獨立的設定表，場次以 id 參照。

### 3.1 Session（場次）

| 欄位 | 型別 | cash | mtt | timed\_mtt | 規則 |
| --- | --- | --- | --- | --- | --- |
| id | string | 必填 | 必填 | 必填 | UUID，系統產生 |
| type | `'cash' \| 'mtt' \| 'timed_mtt'` | 必填 | 必填 | 必填 | 建立後不可變更 |
| startAt | string | 必填 | 必填 | 必填 | `YYYY-MM-DDTHH:00`，本地時間 |
| durationMin | integer | 必填 | 必填 | 必填 | 1–4320（最長 72 小時） |
| buyIns | BuyIn\[\] | 恰 1 筆 | 1–20 筆 | 1–20 筆 | 見 3.2 |
| cashOut | integer | 必填 | 必填 | 必填 | ≥ 0，上限 99,999,999 |
| stakeId | string \| null | 必填 | — | — | 參照 Stake |
| venueId | string \| null | 選填 | 選填 | 選填 | 參照 Venue |
| name | string | 選填 | 選填 | 選填 | 最多 50 字，例：賽事名稱 |
| note | string | 選填 | 選填 | 選填 | 最多 500 字 |
| fieldSize | integer \| null | — | 選填 | — | ≥ 2 |
| finishPlace | integer \| null | — | 選填 | — | 1 ≤ finishPlace ≤ fieldSize |
| createdAt | string | 系統 | 系統 | 系統 | ISO 8601 含時區 |
| updatedAt | string | 系統 | 系統 | 系統 | ISO 8601 含時區 |

「—」表示該類型不使用此欄位，儲存時必須為 `null`。

標準 MTT 填了 finishPlace 就必須同時填 fieldSize；只填 fieldSize 不填 finishPlace 允許。

### 3.2 BuyIn（買入，嵌入在 Session 內）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| amount | integer | 必填，1–99,999,999，**含服務費** |
| fee | integer | 必填，預設 0，0 ≤ fee ≤ amount |

陣列順序即買入順序，第 1 筆是首次進場，其餘為再買入（re-entry）。

### 3.3 Venue（場地）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| id | string | UUID |
| name | string | 必填，1–30 字，去除前後空白後不可與其他場地重複（不分大小寫） |
| archived | boolean | 預設 false |
| sortOrder | integer | 表單選單排序用 |

### 3.4 Stake（盲注級別）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| id | string | UUID |
| sb | integer | 必填，≥ 1 |
| bb | integer | 必填，≥ sb |
| archived | boolean | 預設 false |
| sortOrder | integer | 表單選單排序用 |

顯示名稱由系統產生 `sb/bb`（例：`50/100`），不另存。同一組 sb、bb 不可重複。

### 3.5 Settings（設定，key-value）

| key | 型別 | 用途 |
| --- | --- | --- |
| lastType | string | 新增頁預設選取上次使用的類型 |
| lastVenueByType | Record\<type, venueId> | 各類型預帶上次場地 |
| lastStakeId | string | 現金桌預帶上次盲注 |
| lastBackupAt | string | 上次匯出備份時間，用於備份提醒 |
| recordDraft | object | 新增頁草稿（5.6） |
| profitColorScheme | `'redGain' \| 'greenGain'` | 盈虧顏色慣例，預設 `redGain`（8.3） |

### 3.6 參照完整性

- 場地與盲注級別**不提供實體刪除**，只能封存（archived）。封存後不出現在新增頁選單，但歷史場次與報表仍正常顯示名稱。
- 尚未被任何場次參照的場地或盲注，可以實體刪除。
- 盲注級別被參照後，sb、bb 不可修改（避免歷史 bb/hr 被竄改）；場地名稱可隨時改名。
- 編輯舊場次時，若其場地或盲注已封存，選單仍顯示該選項並標註「已封存」。

### 3.7 Dexie schema（v1）

```
sessions: 'id, type, startAt, venueId, stakeId'
venues:   'id, name, archived'
stakes:   'id, archived'
settings: 'key'
```

之後任何 schema 變更都必須透過 Dexie 的 `version(n).upgrade()` 遷移，不得清除既有資料。

## 4. 計算規則

所有指標只依買入、到手金額、時長計算；服務費已含在買入內，只用於服務費統計，絕不再從盈利扣除。公式一律實作在 `domain/`，每條都要有單元測試。

### 4.1 單一場次

```latex
\text{買入總額} = \sum \text{buyIns[i].amount} \qquad \text{服務費總額} = \sum \text{buyIns[i].fee}
```

```latex
\text{盈利} = \text{cashOut} - \text{買入總額}
```

- 進場次數 = buyIns 筆數。
- 結果判定：盈利 > 0 為「贏」，< 0 為「輸」，= 0 為「平」。「平」不算贏。
- 現金桌單場 bb 盈利 = 盈利 ÷ 該場 bb。

驗算例：限時 MTT 買入 3,400（服務費 400）+ 3,200（服務費 200），到手 9,000。買入總額 6,600、服務費總額 600、進場 2 次、盈利 +2,400。

### 4.2 彙總指標（對一組場次 S）

| 指標 | 公式 | 分母為 0 時 | 顯示格式 |
| --- | --- | --- | --- |
| 盈利 | Σ 盈利 | — | `+$1,523` / `−$4,000` / `$0` |
| 場次數 | S 的筆數 | — | 整數 |
| 贏率 | 贏的場次數 ÷ 場次數 | 顯示 `—` | `13/26（50.0%）` |
| 平均每場盈利 | Σ 盈利 ÷ 場次數 | 顯示 `—` | 金額 |
| 總投入 | Σ 買入總額 | — | 金額 |
| 總到手 | Σ cashOut | — | 金額 |
| ROI | Σ 盈利 ÷ Σ 買入總額 | 顯示 `—` | 百分比，小數 1 位，含正負號 |
| 總時數 | Σ durationMin ÷ 60 | — | `123.5 小時` |
| 時薪 | Σ 盈利 ÷ 總時數 | 顯示 `—` | 金額，後綴 `/hr` |
| 總服務費 | Σ 服務費總額 | — | 金額 |
| 服務費比例 | Σ 服務費總額 ÷ Σ 買入總額 | 顯示 `—` | 百分比，小數 1 位 |

### 4.3 類型專屬指標

| 指標 | 適用 | 公式 | 分母為 0 時 | 顯示格式 |
| --- | --- | --- | --- | --- |
| bb/hr | cash | Σ（盈利ᵢ ÷ bbᵢ）÷ 總時數 | `—` | 小數 1 位，後綴 `bb/hr` |
| ITM% | mtt | 到手金額 > 0 的場次數 ÷ 場次數 | `—` | `8/40（20.0%）` |
| 平均名次百分位 | mtt | 平均（finishPlace ÷ fieldSize），只計兩欄都有填的場次 | `—` | `前 23.5%`，並附註樣本數 `（n=12）` |
| 平均進場次數 | mtt、timed\_mtt | Σ 進場次數 ÷ 場次數 | `—` | 小數 2 位 |
| 平均單次買入（ABI） | mtt、timed\_mtt | Σ 買入總額 ÷ Σ 進場次數 | `—` | 金額 |

bb/hr 按各場自己的 bb 換算後再加總，混合不同盲注級別也正確。平均名次百分位數字越小越好，例如 100 人打到第 10 名為前 10%。

### 4.4 數值與顯示規則（必須）

- 金額顯示為整數、千分位逗號、`$` 前綴。計算出的平均金額在顯示時才四捨五入，以絕對值進位（−2.5 → −3），避免 `Math.round` 對負數的偏差。
- 百分比與 bb/hr 在顯示時四捨五入，內部計算不得提前捨入。
- 負號使用正式減號 `−`（U+2212）顯示；匯出檔一律用 ASCII `-`。
- 正負顏色見第 9 節，正負號永遠顯示，不只靠顏色區分。

### 4.5 期間篩選

以 startAt 的本地日期判斷，與結束時間無關。

| 選項 | 範圍 |
| --- | --- |
| 全部 | 不限 |
| 近三個月 | 今天往前推 3 個月的當天 00:00 起，到今天結束 |
| 近半年 | 今天往前推 6 個月的當天 00:00 起，到今天結束 |
| 自訂 | 起日 00:00 至迄日 23:59，兩端皆含；起日不可晚於迄日 |

月份加減使用 dayjs `subtract(n, 'month')`，月底日期自動收斂（例：5/31 往前 3 個月為 2/28 或 2/29）。未來日期的場次不會出現，因為表單禁止未來時間（第 5 節）。

## 5. 功能：新增場次

新增頁是 App 首頁，目標是最常見的一筆紀錄在 30 秒內完成。表單頂端選類型，欄位隨類型切換；常用值（類型、場地、盲注、日期）自動帶入。

### 5.1 類型選擇

- 分段選擇器三個選項：現金桌 / MTT / 限時 MTT。
- 預設選取 Settings.lastType；首次使用預設現金桌。
- 切換類型時，共用欄位的已填值保留，類型專屬欄位清空。
- 從 MTT 或限時 MTT 切到現金桌時，若買入超過 1 筆，跳出確認視窗「現金桌只有一筆買入，切換後只保留第一筆，確定嗎？」，取消則不切換。

### 5.2 欄位順序

| 順序 | 現金桌 | MTT | 限時 MTT |
| --- | --- | --- | --- |
| 1 | 盲注級別 | 買入列表 | 買入列表 |
| 2 | 買入 + 服務費 | 到手金額 | 到手金額 |
| 3 | 到手金額 | 參賽人數、名次（同一列） | 開始時間 |
| 4 | 開始時間 | 開始時間 | 時長 |
| 5 | 時長 | 時長 | 場地 |
| 6 | 場地 | 場地 | 名稱 |
| 7 | 名稱 | 名稱 | 備註 |
| 8 | 備註 | 備註 | — |

表單底部固定一列即時預覽：「買入 $6,600（2 次）· 服務費 $600 · 盈利 +$2,400」。買入與到手金額都有有效值才顯示盈利，否則顯示 `—`。

### 5.3 欄位行為

**買入列表（MTT、限時 MTT）**

- 預設一列，每列兩個輸入框：買入（含服務費）、服務費。標題寫明「買入（含服務費）」，避免誤填。
- 列表下方「＋ 再買入」按鈕新增一列，新列預填上一列的買入與服務費，可直接修改。
- 第 2 列起每列右側有刪除鈕；只剩 1 列時不顯示刪除鈕。
- 上限 20 列，達上限後按鈕停用。
- 列前標示序號「第 1 次」「第 2 次」。

**現金桌買入**：單一一組買入 + 服務費，沒有再買入按鈕。買入填整場總投入。

**服務費**：預設 0，可留空（留空視為 0）。輸入框旁小字說明「已含在買入內，僅記錄」。

**金額輸入框（所有金額共用）**

- `inputmode="numeric"`，iPhone 叫出數字鍵盤。
- 只接受數字，貼上含逗號或 `$` 的文字時自動移除非數字字元。
- 輸入中即時加千分位逗號顯示。
- 字級至少 16px，避免 iOS Safari 聚焦時自動放大畫面。

**盲注級別（現金桌）**

- 下拉選單列出未封存的盲注，依 sortOrder 排序，預設帶入 Settings.lastStakeId。
- 選單最後一項「＋ 新增盲注」，打開小視窗輸入 sb、bb，儲存後自動選取。
- 尚無任何盲注時，選單顯示「請先新增盲注」並直接開啟新增視窗。

**場地**：行為同盲注選單，含「＋ 新增場地」與「不指定」選項；依類型預帶 Settings.lastVenueByType。

**開始時間**：日期選擇器（年/月/日）+ 小時選單（0–23 時）。預設今天、目前的小時。顯示格式 `2026/09/27 20 時`。

**時長**：小時選單（0–72）+ 分鐘選單（0–55，每 5 分鐘一格）。無預設值，必填。儲存為總分鐘數。

**參賽人數、名次（MTT）**：同一列兩個數字輸入框，顯示為「第 \[ \] 名 / 共 \[ \] 人」。

### 5.4 驗證規則

驗證在按下儲存時執行；已顯示錯誤的欄位，修改後即時重新驗證。儲存按鈕不停用，失敗時捲動到第一個錯誤欄位。

| 規則 | 錯誤訊息 |
| --- | --- |
| 現金桌未選盲注 | 請選擇盲注級別 |
| 買入空白或為 0 | 請填寫買入金額 |
| 服務費 > 該筆買入 | 服務費不可大於買入 |
| 到手金額空白 | 請填寫到手金額，沒拿回請填 0 |
| 任一金額超過 99,999,999 | 金額超出上限 |
| 時長為 0 小時 0 分，或超過 72 小時 | 請選擇 5 分鐘到 72 小時之間的時長 |
| 開始時間晚於現在（依小時比較） | 開始時間不可是未來 |
| 參賽人數 < 2 | 參賽人數至少 2 人 |
| 填了名次未填參賽人數 | 填名次時請一併填寫參賽人數 |
| 名次 > 參賽人數或名次 < 1 | 名次需介於 1 到參賽人數之間 |
| 名稱超過 50 字、備註超過 500 字 | 字數超過上限（輸入框附字數計數） |

### 5.5 儲存後行為

- 寫入 DB 成功後顯示提示「已儲存，盈利 +$2,400」，停留在新增頁。
- 更新 Settings：lastType、lastVenueByType、lastStakeId。
- 表單重置：類型、場地、盲注、日期保留；金額、時長、名稱、備註、參賽人數、名次清空；買入列表回到 1 列。
- 寫入失敗：顯示「儲存失敗，請再試一次」，表單內容不清空。
- 防重複送出：儲存處理中按鈕停用並顯示載入狀態。

### 5.6 草稿

表單有任何輸入時，內容自動存入 Settings.recordDraft（輸入停止 500ms 後寫入）。App 被系統關閉或切換分頁後回到新增頁，自動還原草稿。儲存成功或按下表單右上角「清除」後刪除草稿。

### 5.7 編輯模式

從場次詳情進入編輯時沿用同一個表單元件，差異如下：

- 標題為「編輯場次」，帶入該場次全部欄位。
- 類型選擇器停用，下方小字「類型無法修改，如需更改請刪除後重新新增」。
- 不讀寫草稿、不更新 last\* 設定。
- 儲存後更新 updatedAt，返回場次詳情。
- 有未儲存變更時按返回，跳出「放棄變更？」確認。
- 「開始時間不可是未來」規則同樣適用。

## 6. 功能：報表

報表頁由上到下為：分類頁籤、期間篩選、指標卡、累積盈利曲線、分組統計。切換頁籤或期間時，下方所有區塊同步重算。公式一律來自第 4 節。

### 6.1 分類頁籤與期間

- 頁籤：總體 / 現金桌 / MTT / 限時 MTT，預設總體。
- 期間：全部 / 近半年 / 近三個月 / 自訂，預設全部。選自訂時展開起迄日期選擇器。
- 頁籤與期間的選擇在 App 開啟期間保留，切到其他頁面再回來不重置；App 重啟後回到預設。

### 6.2 各頁籤指標

指標卡以雙欄格狀排列，第一張「盈利」橫跨整列並加大字級。表中 ✓ 為該頁籤顯示的指標，呈現順序即表格由上到下。

| 指標 | 總體 | 現金桌 | MTT | 限時 MTT |
| --- | --- | --- | --- | --- |
| 盈利 | ✓ | ✓ | ✓ | ✓ |
| 場次數 | ✓ | ✓ | ✓ | ✓ |
| 贏率 | ✓ | ✓ | ✓ | ✓ |
| ROI |  |  | ✓ | ✓ |
| 時薪 |  | ✓ | ✓ | ✓ |
| bb/hr |  | ✓ |  |  |
| ITM% |  |  | ✓ |  |
| 平均名次百分位 |  |  | ✓ |  |
| 平均每場盈利 |  | ✓ | ✓ | ✓ |
| ABI |  |  | ✓ | ✓ |
| 平均進場次數 |  |  | ✓ | ✓ |
| 總時數 | ✓ | ✓ | ✓ | ✓ |
| 總投入 | ✓ | ✓ | ✓ | ✓ |
| 總到手 | ✓ | ✓ | ✓ | ✓ |
| 總服務費 | ✓ | ✓ | ✓ | ✓ |
| 服務費比例 | ✓ | ✓ | ✓ | ✓ |

- 總體頁不顯示 ROI、時薪等比率型指標，因為現金桌與錦標賽混算會失真。贏率是例外，沿用參考畫面的習慣。
- 現金桌不顯示 ROI：現金桌買入金額隨個人習慣浮動（可以買 100bb 也可以買 300bb），ROI 沒有參考價值，改看時薪與 bb/hr。
- 總體頁指標卡下方加一個小表：三種類型各自的場次數與盈利，點擊整列跳到該類型頁籤。

### 6.3 累積盈利曲線

- 折線圖，X 軸為場次序號（依 startAt 由舊到新，同時間再依 createdAt），Y 軸為累積盈利。以場次序號而非日期為 X 軸，避免密集打牌的日子擠成一點。
- 資料與當前頁籤、期間一致；期間篩選時從 0 開始累積。
- Y = 0 畫一條虛線基準線。
- 手指點按或滑過曲線時顯示：日期、類型、該場盈利、累積盈利。
- 符合條件的場次少於 2 筆時，圖表區顯示「至少需要 2 場紀錄才能畫出曲線」。
- 超過 500 點時不繪製個別資料點圓圈，只畫線，維持流暢。

### 6.4 分組統計

分組依據以分段選擇器切換，可選項目依頁籤而定：

| 頁籤 | 可選分組 | 各組顯示欄位 |
| --- | --- | --- |
| 總體 | 場地 | 場次數、盈利、總服務費 |
| 現金桌 | 場地、盲注級別 | 場次數、盈利、時薪、bb/hr |
| MTT | 場地、名稱 | 場次數、盈利、ROI、ITM% |
| 限時 MTT | 場地、名稱 | 場次數、盈利、ROI、時薪 |

- 各組依盈利由高到低排序。
- 未指定場地的場次歸到「未指定」組，永遠排最後；未填名稱的歸到「未命名」組，同樣排最後。
- 名稱分組以去除前後空白後完全相同為同一組（大小寫不分）。
- 已封存的場地與盲注照常列入統計。
- 點擊某一組，跳到場次列表並套用同樣的類型、期間與該分組篩選。

### 6.5 空狀態

- 完全沒有紀錄：整頁顯示「還沒有紀錄」與「去新增第一場」按鈕。
- 有紀錄但目前頁籤與期間沒有符合的：指標卡顯示 `—`，圖表與分組區顯示「這個期間沒有紀錄」。

### 6.6 效能

以 5,000 筆場次測試，切換頁籤或期間後到畫面更新完成需在 300ms 內（iPhone 實機）。計算在記憶體內進行，必要時以 memo 快取。

## 7. 功能：場次列表與詳情

紀錄頁列出所有場次，依月份分組、新的在前；點進單筆可檢視完整內容、編輯、複製、刪除。

### 7.1 列表

**排序與分組**：依 startAt 由新到舊，同時間依 createdAt 由新到舊。以月份為分組標題，標題列顯示「2026 年 9 月 · 8 場 · +$12,300」，標題列捲動時黏在頂端。

**單列內容**（左到右）：類型圖示、日期 `09/27`、標題、盈利（含正負號與顏色）、箭頭。標題依序取第一個有值的：

1. name
2. 現金桌：`場地 · 50/100`；錦標賽：場地名稱
3. 現金桌：`50/100`；錦標賽：類型名稱（MTT / 限時 MTT）

錦標賽進場 2 次以上時，標題後加小標籤 `×2`。

**篩選**

- 類型：全部 / 現金桌 / MTT / 限時 MTT。
- 期間：與報表相同的四個選項與規則（第 4.5 節）。
- 關鍵字：比對 name 與 note，不分大小寫、部分符合。
- 從報表分組跳過來時，額外套用場地、盲注或名稱篩選，以可移除的標籤顯示在篩選列（例：`場地：6bet ✕`）。
- 篩選後月份標題的場次數與盈利，只計算符合篩選的場次。
- 列表頂端顯示篩選結果彙總：「共 26 場 · +$39,600」。

**效能**：使用虛擬捲動或分批載入（每批 100 筆），5,000 筆時捲動不卡頓。

**空狀態**：無紀錄時同報表空狀態；篩選無結果時顯示「沒有符合條件的紀錄」與「清除篩選」按鈕。

### 7.2 詳情

顯示內容：

- 頂部：盈利（大字）、類型、標題。
- 基本資料：開始時間、時長（`4 小時 30 分`）、場地、名稱、現金桌盲注。
- 金額：每筆買入明細（第 1 次 $3,400，服務費 $400）、買入總額、服務費總額、到手金額。
- 該場衍生數字：時薪；現金桌加 bb 盈利；MTT 有填名次時加「第 12 名 / 180 人（前 6.7%）」。
- 備註全文（保留換行）。
- 底部小字：建立時間、最後修改時間。
- 場地或盲注已封存時，名稱後標註「（已封存）」。

操作按鈕：編輯、複製為新紀錄、刪除。

### 7.3 編輯

見第 5.7 節。

### 7.4 複製為新紀錄

適合常打的固定賽事。按下後切到新增頁，表單預填類型、場地、盲注、名稱、全部買入列；開始時間設為現在，到手金額、時長、參賽人數、名次、備註留空。若新增頁已有草稿，先跳出「覆蓋目前的草稿？」確認。來源場次的場地或盲注已封存時，該欄留空不預填。

### 7.5 刪除

- 按下刪除跳出確認視窗，內容包含該場日期、標題、盈利。
- 確認後從 DB 實體刪除，返回列表，底部顯示「已刪除 · 復原」提示 5 秒。
- 按復原時，以原始 id、createdAt、updatedAt 原封不動寫回。
- 不提供多選批次刪除。

## 8. 功能：設定與資料管理

設定頁負責常用清單、顯示偏好、備份還原與匯出。因為沒有雲端，備份是防止資料遺失的唯一手段，備份流程必須在 iPhone 主畫面模式實測可用。

### 8.1 場地管理

- 列表顯示名稱與使用場次數，封存項目收在「已封存」折疊區。
- 操作：新增、改名、調整順序（上移/下移按鈕即可，不要求拖拉）、封存、取消封存。
- 使用場次數為 0 時才顯示「刪除」；大於 0 時只能封存。
- 名稱規則見 3.3。

### 8.2 盲注級別管理

- 列表顯示 `sb/bb` 與使用場次數，封存項目收在折疊區。
- 操作：新增、調整順序、封存、取消封存。
- 使用場次數為 0 時可修改 sb、bb 與刪除；大於 0 時兩者都不提供。
- 首次啟動不預載任何盲注，由使用者自行建立。

### 8.3 顯示設定

- 盈虧顏色：「紅色為贏、綠色為輸」（預設，與參考 App 及台股習慣一致）/「綠色為贏、紅色為輸」。存入 Settings.profitColorScheme。
- 深淺色主題跟隨系統，不提供手動切換。

### 8.4 匯出備份（JSON）

檔案格式：

```
{
  "app": "poker-tracker",
  "schemaVersion": 1,
  "exportedAt": "2026-09-28T21:05:00+08:00",
  "sessions": [...],
  "venues": [...],
  "stakes": [...],
  "settings": {...}
}
```

- settings 不包含 recordDraft 與 lastBackupAt。
- 檔名 `poker-backup-YYYYMMDD-HHmm.json`。
- 匯出方式：先判斷 `navigator.canShare({ files })`，可用就開啟 iOS 分享選單（使用者可存到「檔案」或傳到其他 App）；不可用時改用 Blob 下載連結。主畫面模式下的 Blob 下載不穩定，所以分享選單是主要路徑。
- 匯出成功（分享完成或下載觸發）後更新 Settings.lastBackupAt。使用者在分享選單按取消時不更新。

### 8.5 匯入備份（JSON）

- 以檔案選擇器選 `.json` 檔。
- 檢查順序：可解析為 JSON → `app` 為 `poker-tracker` → schemaVersion 不大於目前版本 → 每筆資料通過 Zod 驗證（與第 3 節規則一致）→ 參照的 venueId、stakeId 都存在。任一步失敗就停止，顯示失敗原因與第一筆有問題的資料位置。
- schemaVersion 小於目前版本時，先執行資料遷移再匯入。
- 驗證通過後跳出確認視窗，並排顯示「目前：N 場 / 備份檔：M 場（備份時間）」，警告「匯入會取代目前所有資料，建議先匯出備份」。
- 匯入為**完整取代**，不做合併。清除與寫入在同一個 Dexie transaction 內完成，任何錯誤就整個還原，不留下半套資料。
- 匯入完成後清除 recordDraft、將 lastBackupAt 設為備份檔的 exportedAt，顯示「已匯入 M 場紀錄」。

### 8.6 匯出 CSV

- 匯出全部場次，一場一列，依 startAt 由舊到新。
- 欄位：日期、開始時、類型、場地、盲注、名稱、進場次數、買入總額、服務費總額、到手金額、盈利、時長（分）、參賽人數、名次、備註。
- 編碼 UTF-8 加 BOM，讓 Excel 正確顯示中文；逗號、雙引號、換行依 RFC 4180 跳脫。
- 金額為純數字，無千分位、無 `$`；負數用 ASCII `-`。
- 為防 Excel 公式注入，文字欄位以 `=`、`+`、`-`、`@` 開頭時前面加單引號 `'`。
- 檔名 `poker-sessions-YYYYMMDD.csv`，匯出方式同 8.4。

### 8.7 備份提醒

符合以下任一條件時，在報表頁頂端顯示提醒條「建議備份資料 · 前往備份」，可按 ✕ 暫時關閉到下次開啟 App：

- 從未備份過，且場次數 ≥ 10。
- 距上次備份超過 30 天，且備份後有場次被新增或修改（任一場次 updatedAt > lastBackupAt）。

刪除場次不會觸發此條件，屬已知限制。

### 8.8 資料與系統資訊

- 執行模式：主畫面 App / 瀏覽器分頁（見第 2 節）。
- 持久儲存：已取得 / 未取得。
- 資料量：場次數、場地數、盲注數。
- 上次備份時間（從未備份顯示「從未備份」）。
- App 版本號（讀自 `package.json`）。

### 8.9 清除所有資料

放在設定頁最底部，紅色按鈕。按下後要求輸入「刪除」兩字才能確認，清除所有表（含設定）後回到首次啟動狀態。

### 8.10 版本更新

Service worker 使用 prompt 模式：偵測到新版時底部顯示「有新版本 · 重新載入」，按下才更新，避免填表單到一半被強制重整。草稿機制（5.6）確保更新後表單內容不遺失。

## 9. UI/UX 規範與推薦 Skills

設計方向是「牌桌旁單手快速記帳」的工具型 App：深色優先、數字清楚、按鈕夠大。此節規則優先於任何設計 skill 的建議，兩者衝突時以本節為準。

### 9.1 導覽與畫面清單

底部固定分頁列四個頁籤：新增 / 紀錄 / 報表 / 設定，預設進入新增。

| 畫面 | 入口 | 規格 |
| --- | --- | --- |
| 新增 | 分頁列 | 第 5 節 |
| 紀錄列表 | 分頁列、報表分組點擊 | 7.1 |
| 場次詳情 | 紀錄列表 | 7.2 |
| 編輯場次 | 場次詳情 | 5.7 |
| 報表 | 分頁列 | 第 6 節 |
| 設定 | 分頁列 | 第 8 節 |
| 場地管理 | 設定 | 8.1 |
| 盲注管理 | 設定 | 8.2 |

詳情、編輯、兩個管理頁為推入式子頁，左上角有返回鈕，子頁中底部分頁列仍顯示。每個頁籤記住自己的捲動位置。

### 9.2 版面與操作

- 基準寬度 390px，在 375–430px 間不得出現橫向捲動；大於 480px 時內容置中、最大寬度 480px。
- 使用 `viewport-fit=cover`，頂部與底部以 `env(safe-area-inset-*)` 避開瀏海與 Home 指示條。
- 所有可點擊元件的觸控區域至少 44×44px。
- 新增頁的儲存按鈕與盈利預覽列固定在分頁列上方，不隨表單捲動；iOS 鍵盤彈出時，正在輸入的欄位不得被按鈕列或鍵盤遮住。
- 確認視窗、小視窗用底部彈出面板（bottom sheet），危險操作的確認鈕以紅色標示。
- 提示訊息（已儲存、已刪除）顯示在分頁列上方，不遮擋儲存鈕。

### 9.3 視覺

- 深淺色雙主題跟隨系統，設計時以深色為主（牌室燈光偏暗）。顏色一律用 CSS 變數 token 定義在 `styles/`，元件內不得寫死色碼。
- 盈虧顏色以語意 token `--color-gain`、`--color-loss` 呼叫，由 Settings.profitColorScheme 決定對應紅或綠。深淺兩主題下文字對比度至少 WCAG AA（4.5:1）。
- 字型使用系統字型堆疊（iOS 為 PingFang TC），不載入網路字型，確保離線正常。所有金額與數字使用 `font-variant-numeric: tabular-nums`，上下對齊。
- 圖示使用 lucide-react；三種類型各有固定圖示，全 App 一致。
- 動效只用於狀態變化（頁面推入、面板彈出、提示出現），時長 ≤ 250ms；尊重 `prefers-reduced-motion`。
- 這是個人工具，不需要行銷頁式的裝飾。無漸層背景、無牌桌照片背景，讓數字是畫面主角。

### 9.4 狀態與無障礙

- 每個資料畫面必須有三種狀態：載入中、空、錯誤。
- 表單每個欄位有可見標籤（不只用 placeholder），錯誤訊息顯示在欄位下方並以 `aria-describedby` 關聯。
- 盈虧不只靠顏色：永遠帶正負號。
- 所有操作按鈕使用原生 `<button>`，圖示鈕加 `aria-label`。
