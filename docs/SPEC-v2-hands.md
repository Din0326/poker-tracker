### 0.1 給 Claude Code 的執行規則

- 沿用 v1 第 0 節全部執行規則：規格是唯一依據；遇到沒寫到的行為標註「規格未載明」並詢問，不自行推論；「建議」可調整、「必須」不可變更；註解與文件用繁體中文，識別字用英文；每階段依第 12 節 DoD 自檢。

| 手牌 | Hand | 一手牌的紀錄，存在 `hands` 表（3.1） |
| 簡易手牌 | simple（`kind: 'simple'`） | 快速備忘，欄位少，**不可匯出**（3.9） |
| 完整手牌 | complete（`kind: 'complete'`） | 從發牌到結果完整重建的手牌，可匯出（3.9） |
| 牌局明細 | HandDetail | 完整重建一手牌所需的設定、座位、行動與結果（3.2） |
| 座位 | Seat | 牌桌上的一個位置與該位置玩家的籌碼、手牌（3.3） |
| 行動 | Action | 某位玩家在某條街的一個動作：棄牌、過牌、跟注、下注、加注（3.4） |
| 街 | Street | 下注回合：翻前 preflop、翻牌 flop、轉牌 turn、河牌 river |
| 公牌 | board | 翻牌 3 張、轉牌 1 張、河牌 1 張，共 0–5 張 |
| 位置 | Position | 相對按鈕的位置名稱，例 BTN、SB、BB、UTG、CO（3.7） |
| 你 | Hero | 使用者本人在手牌中的座位；畫面上稱「你」，匯出檔中的名稱預設 `Hero`（7.3） |
| 對手 | villain | Hero 以外的玩家；匯出檔中預設名稱 `Villain<座位號>`（7.3） |
| 按鈕 | button | 莊家位置，畫面上簡稱 BTN |
| 小盲 / 大盲 | sb / bb | 強制下注；本文件的 sb、bb 指**手牌內**的盲注金額（單位：分，3.8），與 v1 Stake 的 sb、bb（單位：元）不同 |
| 前注 | ante | 每位玩家在發牌前放入底池的固定金額 |
| 強制跨注 | straddle | UTG 在發牌前自願放入 2 倍大盲（4.2） |
| 底池 | pot | 所有玩家投入的總和（扣除退回的未跟注部分） |
| 邊池 | side pot | 有玩家全下且金額不同時，依投入層級切出的額外底池；主池為 main pot（4.6） |
| 全下 | all-in | 玩家投入全部剩餘籌碼 |
| 未跟注退回 | uncalled bet | 最後一次下注或加注沒人跟到的部分，退回給該玩家（4.5） |
| 抽水 | rake | 場地從底池抽取的費用（4.8） |
| 收回 | collected | 玩家從底池拿到的金額（已扣抽水，3.5） |
| 淨輸贏 | net / heroNet | 某玩家這手牌的 收回 − 投入；Hero 的淨輸贏稱 heroNet（4.9） |
| 有效籌碼 | effectiveStack | Hero 起始籌碼與其他玩家中最大起始籌碼兩者的較小值（4.9） |
| 牌局類型 | gameType | `'cash'`（現金桌）或 `'tournament'`（錦標賽） |
| 來源 | source | `'manual'`（手動紀錄）或 `'gg'`（從 GG 匯入） |
| 原始文字 | rawText | 匯入時該手牌的原文，保留供日後重新解析（3.1） |
| 匯出序號 | exportSeq | 每手牌一個唯一整數，用來產生匯出檔的手牌編號（7.4） |
| 最小單位 | unit | 金額可以切分的最小量：現金桌 1 分、錦標賽 100 分（= 1 籌碼，3.8） |

## 1. 範圍與非範圍

### 1.1 v2 範圍

- 手動紀錄手牌：簡易模式（備忘）與完整模式（逐街輸入行動，系統自動輪位、算底池與跟注額、防呆）。簡易手牌可之後補齊為完整手牌。
- 手牌可掛在某場次或獨立存在；可設標籤與備註。
- 手牌列表（篩選、排序）與詳情（逐街文字呈現）。
- 匯出完整手牌為 PokerStars 格式 `.txt`（可多手），供 GTO Wizard 等工具讀取。
- PokerStars 格式解析器：解析本 App 自己匯出的文字，用於往返測試（第 9 節）；與 GG 解析器共用核心。**不提供** PokerStars 手牌匯入的畫面（14 節 HQ19）。
- GG 手牌匯入（實驗功能）：單一或多個 `.txt`、PokerCraft 下載的 `.zip`；只支援無限注德州撲克現金桌（8.5）。
- 備份 schemaVersion 3 含手牌；匯入 schemaVersion 1、2 的備份仍可用。
- 牌局範圍：無限注德州撲克，2–10 人桌；現金桌與錦標賽（錦標賽只記錄單手牌的盲注、前注與籌碼，不記錄賽事結構）。

### 1.2 非範圍（v2 不做）

- PLO（Omaha）、短牌（Short Deck / 6+）、限注（Limit）、底池限注（Pot Limit）等其他玩法。
- 錦標賽完整結構：盲注級別表、賽事編號、買入結構、名次與獎金（這些屬於 v1 場次）。
- Run It Twice、EV Cashout、保險、Bomb Pot、補盲（missed / dead blind）、玩家籌碼不足以支付盲注或前注的情況（4.3）、只放大盲前注（BB ante，14 節 HQ6）。
- 其他站點（PokerStars、WPN、iPoker 等）的手牌檔匯入畫面；多站匯入。
- 雲端、同步、分享連結、多人共用。
- 圖像化牌桌重播動畫（詳情只做逐街文字呈現，6.2）。
- 手牌統計（VPIP、PFR、勝率圖等 HUD 類統計）與 GTO 分析本身（交給外部工具）。
- 手牌 CSV 匯出（10.4）。
- 匯入手牌的重新解析畫面（保留 rawText，功能留待之後，14 節 HQ18）。
- **手牌結果不影響任何場次盈利或報表**（4.13）。

## 2. 技術架構補充

沿用 v1 第 2 節技術棧與規範（Dexie、Zod、React、Tailwind、Vitest、Playwright）。

**新增套件**

| 項目 | 選用 | 等級 | 理由 |
| --- | --- | --- | --- |
| zip 解壓 | fflate | 建議 | 純 JS、體積小、支援瀏覽器同步 / 非同步解壓，不需 Web Worker 也可用；只在匯入頁動態載入（`import()`），不影響首頁載入。替代方案：JSZip（較大） |

不新增手牌評估、手牌解析等第三方套件，相關邏輯自行實作在 `domain/hands/`（必須），以確保規則與本文件一致且可單元測試。

**專案結構（建議）**

```
src/
  domain/hands/
    types.ts         Hand、HandDetail、Seat、Action 等型別（第 3 節）
    schemas.ts       Zod schema（第 3 節的欄位規則）
    cards.ts         牌面編碼、驗證、顯示（3.6）
    positions.ts     位置計算（3.7、4.1）
    engine.ts        行動重播、輪位、合法行動、回合結束（4.2–4.5）
    pots.ts          底池、邊池、分配、抽水（4.6–4.8）
    evaluator.ts     牌力評估與英文描述（4.10）
    summary.ts       由 HandDetail 推導摘要欄位、完整判定（3.9）
    sizing.ts        下注快捷金額（4.11）
    format.ts        畫面顯示格式（4.12）
    gtoWizard.ts     GTO Wizard 支援格式判斷（7.8）
    export/pokerstars.ts   PokerStars 文字輸出（第 7 節）
    parse/core.ts          共用解析核心（第 9 節）
    parse/pokerstars.ts    PokerStars 方言（第 9 節）
    parse/gg.ts            GG 方言（第 8 節）
  db/handRepo.ts     hands 表存取
  lib/unzip.ts       zip 解壓（包 fflate，非 domain）
  features/hands/    手牌列表、詳情、編輯器、匯入頁
```

- 必須：`domain/hands/` 不得 import React、Dexie、fflate（同 v1 10.3 P1）。zip 解壓放在 `lib/`。
- 必須：所有手牌畫面字串集中在 v1 既有的字串檔（`src/strings.ts`）的 `hands` 區塊；元件內不得寫死中文或色碼（v1 9.3、10.1）。匯出檔與解析用的英文格式字串（例 `folds`、`*** FLOP ***`）屬於檔案格式，放在 `domain/hands/export`、`parse` 內的常數，不算畫面字串。

**儲存注意事項**：沿用 v1 第 2 節（`navigator.storage.persist()`、主畫面 App 與 Safari 分頁儲存分開、資料遺失只能靠 JSON 備份）。手牌含 GG 原始文字時資料量明顯增加，估計見 11.3。

## 3. 資料模型

手牌存在新的 `hands` 表。完整手牌的牌局明細以嵌入物件 `detail`（HandDetail）儲存；座位、行動、收回都嵌入在 `detail` 內。

### 3.1 Hand（手牌）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| id | string | UUID，系統產生 |
| exportSeq | integer | 系統產生，1–99,999,999,999,999，全表唯一，建立後不可變更（7.4） |
| kind | `'simple' \| 'complete'` | 系統依 3.9 判定後寫入，不可由使用者直接設定；儲存與匯入時必須等於 3.9 的判定結果 |
| source | `'manual' \| 'gg'` | 建立後不可變更 |
| gameType | `'cash' \| 'tournament'` | 必填。有 detail 時建立後不可變更（變更需清除 detail，5.8） |
| sessionId | string \| null | 選填，參照 Session（v1 3.1）；null 表示獨立手牌。規則見 3.11 |
| playedAt | string | 必填，本地時間 `YYYY-MM-DDTHH:mm:ss`，不含時區。手動紀錄秒數固定 `00`，不可晚於現在（依分鐘比較）；GG 匯入沿用原文時間（8.3） |
| bb | integer \| null | 大盲（分，3.8）。有 detail 時必須等於 `detail.bb`；無 detail 時選填，≥ 1、≤ 9,999,999,900，用於以 bb 顯示結果 |
| heroCards | Card\[\] | 0 或 2 張（3.6）；完整手牌必須 2 張 |
| heroPosition | Position \| null | 3.7。有 detail 時必須等於依 detail 計算的 Hero 位置；無 detail 時選填 |
| board | Card\[\] | 0、3、4 或 5 張（依序為翻牌 3 張、轉牌、河牌） |
| heroNet | integer \| null | Hero 淨輸贏（分，可為負）。完整手牌必須等於 4.9 的計算值；有 detail 但未完成時必須為 null；無 detail 時選填，絕對值 ≤ 9,999,999,900 |
| detail | HandDetail \| null | 3.2。null 表示純備忘的簡易手牌 |
| tags | string\[\] | 0–10 個；每個去除前後空白後 1–20 字；同一手內不可重複（去除前後空白後比較，不分大小寫）；儲存去除前後空白後的值；不得為 null 或省略，沒有時為 `[]` |
| note | string \| null | 選填，最多 1,000 字；未填為 null |
| sourceHandId | string \| null | source 為 `gg` 時必填：原站手牌編號含前綴，例 `RC1000000001`，1–40 字元，僅英數字；manual 時必須為 null |
| rawText | string \| null | source 為 `gg` 時必填：該手牌原文（已正規化換行為 `\n`、去除 BOM 與前後空白行），最多 20,000 字元；manual 時必須為 null |
| parserVersion | integer \| null | source 為 `gg` 時必填：解析器版本，v2.0 為 1；manual 時必須為 null |
| createdAt | string | 系統，ISO 8601 含時區 |
| updatedAt | string | 系統，ISO 8601 含時區 |

**摘要欄位**：`bb`、`heroCards`、`heroPosition`、`board`、`heroNet` 稱為摘要欄位，讓列表、篩選不必解析 detail。

- 必須：`detail` 不為 null 時，摘要欄位一律由 `summarizeHand(detail, gameType)`（`domain/hands/summary.ts`）推導後寫入，UI 不得直接編輯；儲存、匯入時驗證摘要欄位與推導結果完全一致，不一致即驗證失敗。
- `detail` 為 null 時，摘要欄位是使用者輸入的備忘值（5.2）。
- 必須：所有欄位都必須存在，選填未填時為 null（或空陣列），不得省略（與 v1 一致）。

### 3.2 HandDetail（牌局明細，嵌入在 Hand 內）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| tableSize | integer | 2–10，桌子座位數（例 6 表示 6-max） |
| buttonSeat | integer | 按鈕座位號，必須是 seats 中的座位 |
| heroSeat | integer | Hero 座位號，必須是 seats 中的座位 |
| sb | integer | 小盲（分），≥ 1 |
| bb | integer | 大盲（分），≥ sb |
| ante | integer | 前注（分），≥ 0；0 表示沒有前注；> 0 時每位玩家都放（4.2） |
| straddle | integer | 0 或恰為 2 × bb；> 0 時只允許 seats ≥ 3 位（4.2，14 節 HQ5） |
| seats | Seat\[\] | 2–tableSize 筆，依 seatNo 由小到大排列，seatNo 不重複（3.3） |
| actions | Action\[\] | 0–200 筆，依發生順序（3.4） |
| rake | integer | 抽水（分），≥ 0，≤ 底池總額；gameType 為 `tournament` 時必須為 0 |
| collected | Collected\[\] | 3.5；手牌未結束時必須為 `[]` |

金額欄位（sb、bb、ante、straddle、rake、Seat.stack、Action.to、Collected.amount）上限皆為 9,999,999,900（= 99,999,999.00，與 v1 金額上限一致），且必須是該手最小單位（3.8）的整數倍。

### 3.3 Seat（座位，嵌入在 HandDetail 內）

只記錄有玩家且被發牌的座位；空位不建立 Seat。

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| seatNo | integer | 1–tableSize |
| stack | integer | 起始籌碼（分，發牌前、放前注與盲注前），必須大於該座位要放的前注 + 盲注 / straddle（4.3） |
| cards | Card\[\] | 0 或 2 張。Hero 座位必須等於 Hand.heroCards（有 detail 時 heroCards 由此推導）。其他座位只有在該玩家進入攤牌且亮牌時才可有 2 張；棄牌的玩家必須為 `[]` |
| mucked | boolean | 只有進入攤牌、沒有亮牌的對手可為 true（4.7）；其餘必須為 false。Hero 不可為 true |
| name | string \| null | 原站玩家名稱（GG 匯入時寫入；需符合 7.3 的名稱規則，否則為 null）；手動紀錄為 null |

### 3.4 Action（行動，嵌入在 HandDetail 內）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| street | `'preflop' \| 'flop' \| 'turn' \| 'river'` | 必須依 preflop → flop → turn → river 的順序，不可倒退 |
| seatNo | integer | 必須是 4.2 規則下輪到行動的座位 |
| type | `'fold' \| 'check' \| 'call' \| 'bet' \| 'raise'` | 必須是 4.3 的合法行動 |
| to | integer \| null | bet、raise 必填：行動後該玩家**這條街**的累計投入（「加注到」金額，不含前注）；fold、check、call 必須為 null |

- 前注、盲注、straddle 不存成 Action，由 HandDetail 的設定推導（4.2）。
- 跟注金額與「是否全下」不儲存，由重播推導（4.3），避免資料自相矛盾。
- 必須：任何儲存的 detail，從第一筆行動重播到最後一筆都必須合法（4.2–4.4）；不合法即驗證失敗。

### 3.5 Collected（收回，嵌入在 HandDetail 內）

| 欄位 | 型別 | 規則 |
| --- | --- | --- |
| seatNo | integer | 必須是對該底池有資格的玩家（4.6） |
| potIndex | integer | 0 = 主池，1 起為邊池，依 4.6 的切分順序 |
| amount | integer | ≥ 1（分） |

- 手動紀錄：由 4.7、4.8 自動計算，使用者不可編輯。
- GG 匯入：取自原文的 `collected` 行（8.3），並通過 4.8 的驗證。
- 同一 seatNo 與 potIndex 組合最多一筆；陣列依 potIndex、再依 seatNo 由小到大排序。
- 必須：Σ amount = 底池總額 − rake。

### 3.6 Card（牌面編碼）

- 兩字元字串：點數 + 花色。點數 `2 3 4 5 6 7 8 9 T J Q K A`（`T` 代表 10），花色 `s`（♠）`h`（♥）`d`（♦）`c`（♣）。正規表示式 `^[2-9TJQKA][shdc]$`，區分大小寫（點數大寫、花色小寫）。
- 同一手牌內，heroCards、board、所有 Seat.cards 合計不得有重複的牌（52 張中每張最多出現一次）。
- 畫面顯示：點數 `T` 顯示為 `10`，花色以符號 ♠♥♦♣ 顯示（例 `A♠ K♦`、`10♥`）；花色顏色用 token `--color-suit-red`（♥♦）、`--color-suit-black`（♠♣），但花色永遠以符號表示，不只靠顏色（v1 9.4）。

### 3.7 Position（位置）

儲存值：`'BTN' | 'SB' | 'BB' | 'UTG' | 'UTG1' | 'UTG2' | 'UTG3' | 'LJ' | 'HJ' | 'CO'`。畫面顯示 `UTG1` 為 `UTG+1`，其餘照原字。

依**被發牌的玩家數 n**（seats 筆數，不是 tableSize）決定，從按鈕順時針（座位號遞增並循環）依序為：

| n | 按鈕起順時針的位置 |
| --- | --- |
| 2 | BTN（同時是小盲）、BB |
| 3 | BTN、SB、BB |
| 4 | BTN、SB、BB、CO |
| 5 | BTN、SB、BB、HJ、CO |
| 6 | BTN、SB、BB、UTG、HJ、CO |
| 7 | BTN、SB、BB、UTG、LJ、HJ、CO |
| 8 | BTN、SB、BB、UTG、UTG1、LJ、HJ、CO |
| 9 | BTN、SB、BB、UTG、UTG1、UTG2、LJ、HJ、CO |
| 10 | BTN、SB、BB、UTG、UTG1、UTG2、UTG3、LJ、HJ、CO |

- 2 人時按鈕即小盲，位置記為 `BTN`。
- 有 straddle 時，straddle 玩家的位置名稱不變（例：6 人桌仍為 UTG），畫面另加「Straddle」標示。
- 簡易手牌選位置時，選單列出全部 10 種與「不指定」。

### 3.8 金額單位（必須）

- 手牌內所有金額一律以**分**（1/100 元）為單位的整數儲存，不允許小數。例：$0.05 → 5、$1 → 100、50 元 → 5,000。
- 理由：v1 金額以元為整數，無法表示線上小額盲注（$0.05/$0.10）；改以分儲存可同時表示現場與線上牌局。手牌金額與 v1 場次金額**不互相換算、不互相加總**（4.13），單位不同不會造成混用。
- 最小單位（unit）：gameType 為 `cash` 時 1（分）；`tournament` 時 100（= 1 籌碼）。錦標賽所有金額必須是 100 的倍數（籌碼為整數）。
- 輸入：現金桌金額輸入框 `inputmode="decimal"`，最多 2 位小數；錦標賽 `inputmode="numeric"`，只接受整數籌碼。字串轉成分必須精確：以字串拆整數與小數部分再組成整數（「0.05」→ 5、「12.5」→ 1,250），不得以浮點數乘 100 後截斷（同 v1 5.3 比例輸入規則）。
- 從 v1 場次帶入盲注時（5.1），Stake 的 sb、bb（元）× 100。
- 上限：單一金額 ≤ 9,999,999,900；10 人各自上限相加 < `Number.MAX_SAFE_INTEGER`，加總計算不會溢位。
- 不另設幣別欄位（同 v1 第 1 節「不做多幣別」）。線上 GG 的美元與現場的新台幣在本 App 中都只是「金額」。此決定見 14 節 HQ1。

### 3.9 完整 / 簡易的判定（必須）

`kind` 由 `classifyHand(hand)` 判定，結果寫入 `kind`：

**完整手牌**（`kind: 'complete'`）必須同時符合：

1. `detail` 不為 null，且通過結構驗證（下方）。
2. Hero 座位有 2 張手牌。
3. 手牌已結束（4.4 的「手牌結束」）。
4. 公牌張數符合實際進行到的街：結束於翻前（其餘玩家都棄牌）為 0 張；結束於翻牌、轉牌、河牌分別為 3、4、5 張；有全下而剩餘公牌自動發完（runout，4.4）時必須 5 張。
5. 若進入攤牌：每位攤牌對手都有 2 張手牌或 `mucked: true`，且每個底池至少一位有資格的玩家有手牌（4.7）。
6. `collected` 符合 3.5 與 4.8。

**簡易手牌**（`kind: 'simple'`）：不符合完整條件的手牌，分兩種：

- 純備忘：`detail` 為 null，只有 5.2 的備忘欄位。
- 未完成的完整紀錄：`detail` 不為 null 但未符合上述 2–6（例如只記到翻牌）。此時 detail 仍必須通過結構驗證，`collected` 為 `[]`，`heroNet` 為 null。可從詳情「繼續補齊」（5.8）。

**結構驗證**（任何非 null 的 detail 都必須通過）：3.2–3.5 的欄位規則、3.6 牌不重複、行動依 4.2–4.4 重播合法、公牌張數不超過「已進行到的街」加一條（可以在翻前下注結束時先輸入翻牌，但不能在翻前還沒結束時輸入翻牌；翻牌有行動時必須已有 3 張公牌，轉牌、河牌同理；進入自動發完（4.4）後可直接到 5 張）。

**簡易手牌不可匯出**（7.1）。

| --- | --- | --- | --- |

### 3.11 參照完整性

- `sessionId` 必須參照存在的場次，或為 null。
- 類型相容：gameType `cash` 只能關聯 type 為 `cash` 的場次；`tournament` 只能關聯 `mtt` 或 `timed_mtt` 的場次。
- 關聯場次不限制 playedAt 必須落在場次時間內，也不限制盲注必須等於場次盲注（只在新增時預帶，5.1）。
- 刪除場次：掛在底下的手牌**轉為獨立手牌**（sessionId 改為 null），不刪除手牌（6.5，14 節 HQ4）。
- 刪除手牌：實體刪除，可在 5 秒內復原（6.4）。

### 3.12 Dexie schema version 3

v1 3.7 的 version 1、version 2 定義保留，不得修改或刪除。新增 version 3：

```
db.version(1).stores({ ...v1 定義 })          // 保留，不得刪除
db.version(2).stores({ ...v2 定義 }).upgrade(upgradeToV2)   // 保留，不得刪除
db.version(3).stores({
  sessions: 'id, type, startAt, venueId, stakeId',
  venues:   'id, name, archived',
  stakes:   'id, archived',
  settings: 'key',
  hands:    'id, playedAt, sessionId, &exportSeq, sourceHandId, *tags',
}).upgrade(upgradeToV3)
```

索引用途：

| 索引 | 用途 |
| --- | --- |
| playedAt | 列表依時間排序與期間篩選 |
| sessionId | 場次詳情列出該場手牌、刪除場次時找出要轉為獨立的手牌。null 值不會被 IndexedDB 索引，正好排除獨立手牌 |
| &exportSeq | 唯一索引，保證匯出編號不重複；取最大值配發新序號（7.4） |
| sourceHandId | GG 匯入去重（8.6）。manual 手牌為 null，不進索引 |
| \*tags | multiEntry，依標籤篩選與標籤建議 |

- 必須：不得為任何布林欄位（例如 Seat.mucked）建索引；IndexedDB 的索引鍵不接受 boolean（見 `src/db/schema.ts` 註解）。`kind`、`source`、`gameType`、`heroPosition` 本版也不建索引，相關篩選在記憶體內進行（11.1）。
- 必須：`upgradeToV3` 不讀寫任何既有表（sessions、venues、stakes、settings 的每一筆資料、包含 `updatedAt`，升級前後逐欄相同）。`hands` 表由 Dexie 依 stores 定義自動建立為空表。`upgradeToV3` 可以是空函式；保留這個函式是為了讓測試可注入失敗（同 `createDb` 的 `upgradeV2` 選項，建議新增 `upgradeV3` 選項）。
- 必須：v1 3.7 的其他規則全部適用於 version 3：不得刪除、重建資料庫或清空任何表；遷移失敗時資料維持 version 2，畫面顯示「資料升級失敗，請關閉 App 後重新開啟；你的資料沒有遺失」，不得進入可寫入的畫面；處理 `versionchange` 事件。
- 版本號：`DB_VERSION` 由 2 改為 3。

## 4. 牌局規則與計算

本節規則全部實作在 `domain/hands/`，每條都要有單元測試（12.2）。「順時針」指座位號遞增，超過 tableSize 後回到最小的座位號；只計算 seats 中存在的座位（空位跳過）。

### 4.1 座位與位置

- 按鈕：`buttonSeat`，必須是有玩家的座位（不支援死按鈕）。
- 3 人以上：小盲 = 按鈕順時針下一位；大盲 = 小盲順時針下一位。
- 2 人：按鈕即小盲；另一位是大盲。
- straddle 玩家 = 大盲順時針下一位（3 人桌即按鈕）。
- 位置名稱依 3.7。

### 4.2 強制下注與行動順序

**發牌前放入（依序）**：

1. ante > 0 時，每位玩家各放 ante。前注不計入任何一條街的「該街投入」，只計入底池。
2. 小盲放 sb、大盲放 bb；straddle > 0 時 straddle 玩家放 straddle。這三者計入翻前的「該街投入」。

**翻前**：

- 目前下注額 B = max(bb, straddle)；最小加注增量 L = B（沒有 straddle 時為 bb；有 straddle 時為 straddle，即最小加注到 2 × straddle）。
- 第一位行動者：沒有 straddle 時為大盲順時針下一位；有 straddle 時為 straddle 玩家順時針下一位。2 人時為按鈕（小盲）。
- 大盲（有 straddle 時為 straddle 玩家）在其他人都只跟注時仍有一次行動機會（option：過牌或加注）。

**翻牌、轉牌、河牌**：

- B = 0；L = bb。
- 第一位行動者：按鈕順時針下一位仍在牌局中（未棄牌）且未全下的玩家。2 人時為大盲。

**輪位**：每次行動後，輪到順時針下一位「未棄牌、未全下、且這回合還需要行動」的玩家（4.4）。

### 4.3 合法行動（必須）

符號：A = 行動者該街已投入、S = 行動者剩餘籌碼、B = 目前下注額、L = 最小加注增量、toCall = B − A。

| 行動 | 合法條件 | 結果 |
| --- | --- | --- |
| fold（棄牌） | 任何時候都合法 | 行動者退出這手 |
| check（過牌） | toCall = 0 | — |
| call（跟注） | toCall > 0 | 投入 min(toCall, S)；投入後 S = 0 即為全下 |
| bet（下注） | B = 0（翻前永遠不會成立）；bb ≤ to ≤ S，或 to = S（籌碼不足 bb 時只能全下） | 該街投入變為 to；B = to；L = max(to, bb) |
| raise（加注） | B > 0；S > toCall；行動者「可加注」（下方）；B + L ≤ to ≤ A + S，或 to = A + S（全下但不足最小加注）；且 to > B | 該街投入變為 to；增量 r = to − B；r ≥ L 為**完整加注**：L = r，重新開放行動；r < L 為**不完整加注**（只可能是全下）：L 不變，不重新開放 |

- 「可加注」：自上一次完整加注（或本回合開始）之後，行動者還沒行動過；或行動者面對的是完整加注。實作方式（建議）：維護集合 `actedSinceFullRaise`，回合開始時為空；每次完整加注（含下注）後重設為只含該行動者；其他行動把行動者加入集合。行動者在集合中時不可加注，只能跟注或棄牌。
- 籌碼限制（必須）：每位玩家的 stack 必須**大於**他要在發牌前放入的前注 + 盲注（或 straddle）。不支援發牌前就全下（1.2）。手動紀錄違反時顯示 5.5 錯誤；匯入時拒絕該手（8.5）。
- 手動紀錄 UI：toCall > 0 時不顯示「過牌」；toCall = 0 時不顯示「棄牌」與「跟注」（避免誤觸；引擎仍接受 toCall = 0 時棄牌，供匯入使用）；不可加注時不顯示「加注」（5.3）。

### 4.4 回合結束、手牌結束與自動發完

**回合結束**：符合任一條件即結束目前這條街：

- 只剩 1 位未棄牌的玩家 → **手牌結束**（其他人都棄牌）。
- 每位未棄牌且未全下的玩家都已在本回合行動過（發牌前的強制下注不算行動），且該街投入都等於 B；或未棄牌且未全下的玩家只剩 0 位；或只剩 1 位且他的該街投入 ≥ B。

**回合結束後**：

1. 依 4.5 退回未跟注的部分。
2. 若手牌結束，進入結算（4.8）。
3. 若是河牌回合結束 → 進入攤牌（4.7）。
4. 若未棄牌且未全下的玩家 ≤ 1 位 → **自動發完**（runout）：之後的街沒有任何行動，公牌直接發到 5 張，然後攤牌。
5. 否則進入下一條街（4.2）。

**手牌結束**的兩種情況：其他人都棄牌；或攤牌完成。

### 4.5 未跟注退回

每條街回合結束時（含手牌因棄牌而結束時），比較所有玩家（含已棄牌者）在**該街**的投入：若最高者只有 1 位，且高於第二高者，差額退回給最高者。

- 例：翻前所有人棄牌到大盲（盲注 0.5 / 1），大盲該街投入 1、第二高為小盲 0.5，退回 0.5 給大盲（12.2 HC2）。
- 退回的金額不計入底池與該玩家的投入。

### 4.6 底池與邊池

- 每位玩家的**總投入** = 前注 + 各街投入 − 退回。
- **底池總額**（total pot）= Σ 所有玩家總投入。
- 邊池切分（必須）：
  1. 取「未棄牌且全下」玩家的總投入，加上所有未棄牌玩家中的最大總投入，去重後由小到大排序，得到層級 c₁ < c₂ < … < cₖ。
  2. 第 j 個池（j = 1…k）的金額 = Σ（所有玩家，含已棄牌者）[min(總投入, cⱼ) − min(總投入, cⱼ₋₁)]，c₀ = 0。
  3. 第 j 個池的資格者 = 未棄牌且總投入 ≥ cⱼ 的玩家。
  4. 相鄰兩池資格者完全相同時合併為一個池。
  5. 金額為 0 的池移除。依序編號 potIndex 0（主池）、1、2…（邊池）。
- 手牌因棄牌而結束時只有 1 個池，資格者為剩下的那位玩家。

### 4.7 攤牌與贏家

- 攤牌者：手牌於河牌回合結束或自動發完時，所有未棄牌的玩家。
- 每位攤牌對手必須是下列其一：
  - 亮牌：Seat.cards 為 2 張。
  - 蓋牌：`mucked: true`，cards 為 `[]`。蓋牌視為放棄所有底池。
- Hero 在攤牌時一律亮牌（不支援 Hero 蓋牌，14 節 HQ10）。
- 每個池的贏家：在該池資格者中、有手牌（亮牌或 Hero）的玩家裡，牌力最高者（4.10）；同牌力則平分。某個池的資格者都沒有手牌時，該 detail 不算完整（3.9 第 5 點），畫面顯示 5.5 的錯誤。
- 手動紀錄不能手動指定贏家；贏家完全由牌力決定。

### 4.8 抽水與分配

- rake 只在 gameType 為 `cash` 時可大於 0。
- 扣除順序（必須）：從主池（potIndex 0）開始扣，主池不足時剩餘部分從下一個池扣，依此類推（14 節 HQ7）。
- 每個池扣除抽水後的金額平分給該池贏家：以最小單位（3.8）切分，餘數以 1 個單位為一份，從按鈕順時針下一位起，依序發給該池的贏家（12.2 HC6）。
- 手動紀錄的 `collected` 由此計算；每位贏家在每個池各一筆。
- 驗證（手動與匯入都適用）：
  - Σ collected.amount = 底池總額 − rake。
  - 每筆 collected 的 seatNo 必須是該 potIndex 的資格者；同一池的 collected 合計不得超過該池扣除抽水後的金額。
  - potIndex 必須小於 4.6 切出的池數。
- 匯入的手牌以原文的收回金額為準（8.3），不重算分配；但贏家集合必須與 4.7 的判定一致（8.3）。

### 4.9 結果

- 每位玩家淨輸贏 net = Σ 該玩家 collected − 總投入。
- **恆等式**：Σ 所有玩家 net = −rake（可作為測試檢查式）。
- heroNet = Hero 的 net；只有完整手牌才有值。
- 有效籌碼 effectiveStack = min(Hero 起始籌碼, 其他玩家起始籌碼的最大值)。

### 4.10 牌力評估與描述

- 以 Hero 或攤牌者的 2 張手牌 + 5 張公牌，取 7 張中最佳 5 張。
- 牌型大小（高到低）：同花順、四條、葫蘆、同花、順子、三條、兩對、一對、高牌。同牌型依 5 張逐張比較（踢腳）。A 可當 1 組成 A-2-3-4-5（最小的順子，記為 Five high）。花色不分大小。
- 匯出檔需要英文描述（7.7 第 26、36 行），格式如下（**需驗證**，見 14 節 HQ12）：

| 牌型 | 描述格式 | 例 |
| --- | --- | --- |
| 高牌 | `high card <Rank>` | `high card Ace` |
| 一對 | `a pair of <Ranks>` | `a pair of Kings` |
| 兩對 | `two pair, <Ranks> and <Ranks>` | `two pair, Kings and Sevens` |
| 三條 | `three of a kind, <Ranks>` | `three of a kind, Nines` |
| 順子 | `a straight, <Rank> to <Rank>` | `a straight, Ten to Ace`、`a straight, Ace to Five` |
| 同花 | `a flush, <Rank> high` | `a flush, Ace high` |

### 4.11 下注快捷金額

符號：P = 目前底池（所有玩家已放入的前注與各街投入，含本街，未扣退回）、C = toCall、B = 目前下注額、unit = 最小單位。

- 分數 f 的目標「加注到」金額：`target = B + round((P + C) × f)`。B = 0 時即下注 `round(P × f)`。
  - f = 1 即底池限注的「底池加注」：例翻前盲注 1/2、UTG 面對 2：B 2 + (3 + 2) = 7。
- 捨入（必須）：以整數運算四捨五入到 unit 的整數倍，0.5 進位，演算法同 v1 4.6（分子 N、分母 D，q = ⌊N ÷ D⌋、r = N − q × D，2r ≥ D 則進位）。⅔ 以 N = (P + C) × 2、D = 3 × unit 計算後再乘 unit；½ 以 N = (P + C)、D = 2 × unit。
- 夾限：target < 最小合法金額（bet 為 bb，raise 為 B + L）時改為最小合法金額；target ≥ 全下金額（A + S）時改為全下。
- 快捷按鈕：`½ 池`、`⅔ 池`、`底池`、`全下`、`最小`，每顆按鈕上顯示計算後的金額（例「⅔ 池 $3.67」）；夾限後等於全下時按鈕文字改為「全下 $79.50」。
- 驗算：翻牌底池 $5.50、無人下注：½ 池 $2.75、⅔ 池 $3.67（366.67 分進位）、底池 $5.50。轉牌前底池 $12.50、對手下注 $8 後輪到你（P = 20.50、C = 8、B = 8）：½ 池加注到 $22.25、⅔ 池加注到 $27.00、底池加注到 $36.50（12.2 HC15）。

### 4.12 顯示規則（必須）

沿用 v1 4.4，並補充：

- 現金桌金額：`$` 前綴、千分位逗號。一手牌中只要有任何金額不是 100 分的整數倍（含 sb、bb、ante、straddle、籌碼、行動、收回、抽水、結果），**這一手所有金額**一律顯示 2 位小數（`$0.50`、`$84.00`）；否則一律顯示整數（`$50`、`$8,400`）。同一手內小數位數一致。
- 錦標賽金額（籌碼）：不加 `$`，整數、千分位逗號（`1,500`）。
- 結果（heroNet）：正負號永遠顯示，負號用 `−`（U+2212），正負顏色用 `--color-gain`、`--color-loss`（v1 9.3）。0 不帶正負號，依該手的格式顯示為 `$0`、`$0.00` 或（錦標賽）`0`，同 v1。
- bb 顯示：金額 ÷ bb，小數 1 位，後綴 ` bb`，含正負號（`+84.0 bb`、`−12.5 bb`）；以絕對值四捨五入（同 v1 4.4）。有效籌碼也以 bb 顯示（`100.0 bb`）。bb 為 null 的簡易手牌不顯示 bb。
- 列表與詳情的結果：有 bb 時主要顯示 bb，金額為次要；沒有 bb 時只顯示金額；heroNet 為 null 時顯示 `—`。
- 匯出檔的格式另見 7.6，不適用本節。

### 4.13 與場次盈利的關係（必須）

- 手牌的 heroNet **不影響**任何場次的 cashOut、盈利、你的盈利，也**不計入** v1 第 4、6、7 節的任何指標、報表、曲線、分組統計、列表彙總與 CSV。
- 手牌只是紀錄；即使某場次底下所有手牌的 heroNet 加總不等於該場盈利，也不提示、不修正。
- 手牌列表不顯示 heroNet 的加總（6.1），避免與場次盈利混淆。

### 5.3 完整模式

完整模式是逐步流程，頂端顯示進度「設定 › 翻前 › 翻牌 › 轉牌 › 河牌 › 結果」，已完成的步驟可點擊回看（回看時只能檢視；要修改請用「復原上一步」退回，見下方）。尚未到達或因手牌提早結束而不會到達的步驟顯示為停用。

**步驟 1：牌局設定**

| 順序 | 欄位 | 規則 |
| --- | --- | --- |
| 1 | 時間、關聯場次、牌局類型 | 同 5.2 |
| 2 | 人數（桌子座位數） | 分段選擇器 2 / 6 / 8 / 9，另有「其他」可選 3–10；預設帶入 lastHandSetup |
| 3 | 盲注 | 小盲、大盲兩個金額輸入框（3.8） |
| 4 | 前注 | 金額輸入框，預設 0 |
| 5 | Straddle | 開關，預設關；開啟時金額固定為 2 × 大盲並顯示（不可改） |
| 6 | 預設籌碼 | 金額輸入框，預設 100 × 大盲；下方小字以 bb 顯示（「100.0 bb」）。修改後套用到所有「未個別修改」的座位 |
| 7 | 座位圖 | 依人數畫出座位 1–N 的清單（每座位一列，不畫圓桌，確保 375px 寬度下觸控區足夠）。每列：座位號、位置名稱（依目前按鈕即時計算）、「空位」開關、籌碼輸入框（預設 = 預設籌碼）、「按鈕」單選、「你」單選。預設：全部有人、按鈕在座位 1、你在 lastHandSetup 記住的座位（無則座位 1） |
| 8 | 你的手牌 | 2 個牌位，選牌器（5.4）；這一步就要選 |

按「開始翻前」時驗證本步驟（5.5）；通過後進入步驟 2。

**步驟 2–5：翻前、翻牌、轉牌、河牌**

- 翻牌、轉牌、河牌步驟開始時，先要求選公牌（翻牌 3 張、轉牌 1 張、河牌 1 張），選完才顯示行動按鈕。
- 畫面上方：本手行動紀錄（依街分組，最新在下）、目前公牌、底池 P、目前下注額。
- 畫面下方固定的行動列（同 v1 9.2「固定在分頁列上方」）：
  - 輪到誰：「輪到 CO（座位 3）· 剩 $97.50」；輪到 Hero 時標示「你」。
  - 行動按鈕（依 4.3 只顯示合法者）：`棄牌`、`過牌`、`跟注 $1.50`（顯示跟注金額；不足時為「跟注 $14.50 全下」）、`下注` 或 `加注`。
  - 按 `下注` / `加注` 開啟 bottom sheet：快捷按鈕 `最小`、`½ 池`、`⅔ 池`、`底池`、`全下`（4.11，按鈕顯示金額），與自訂金額輸入框（標籤「下注到」/「加注到」，3.8 輸入規則），按「確定」送出。自訂金額不合法時顯示 5.5 錯誤，不送出。
  - `復原上一步`（圖示鈕，`aria-label`「復原上一步」）：移除最後一筆行動；若最後一步是選公牌，則清除該街公牌並回到上一街結束狀態。可一路退回到步驟 1 之後的狀態。
- 每次行動後依 4.2–4.4 自動輪到下一位；回合結束時自動前進到下一步驟（或自動發完、或結算）。
- 自動發完（4.4）時，一次要求選完剩餘公牌，然後進入步驟 6。
- 手牌因其他人都棄牌而結束時，直接進入步驟 6。

**步驟 6：攤牌 / 結果**

- 有攤牌時：列出每位攤牌對手，各有 2 個牌位與「蓋牌」選項（二擇一）。
- 現金桌顯示「抽水」金額輸入框，預設 0；錦標賽不顯示（rake 固定 0）。
- 系統依 4.6–4.9 即時顯示：每個底池金額與贏家、每位玩家淨輸贏、Hero 結果（「你 +$84.00 · +84.0 bb」）。
- 標籤、備註欄位（同 5.2）在此步驟。
- 按「儲存」：通過 3.9 完整條件時存為完整手牌；否則顯示第一個錯誤並捲動到該處。

**任何步驟都可「暫存為簡易」**（頁面右上選單）：以目前狀態存為未完成的完整紀錄（3.9 簡易手牌的第二種），detail 必須通過結構驗證；結構驗證不通過時（例如步驟 1 尚未通過），提示「牌局設定還沒完成，無法暫存」。

### 5.4 選牌器

以 bottom sheet 呈現，採「先選點數、再選花色」兩段式，確保 375px 寬度下每個按鈕 ≥ 44×44px（52 張一次排開每格不到 30px，違反 v1 9.2）：

- 頂端：本次要選的牌位（例：翻牌 3 個牌位），目前作用中的牌位有外框；點擊已填的牌位可清除並重選。
- 點數區：13 顆按鈕（A K Q J 10 9 8 7 6 5 4 3 2），排成 7 + 6 兩列。
- 花色區：4 顆按鈕（♠ ♥ ♦ ♣），選了點數後啟用。
- **已選鎖定（必須）**：這手牌中其他位置已使用的牌（Hero 手牌、公牌、對手攤牌牌）不可再選。花色按鈕對應的牌已使用時停用（`disabled`，並在按鈕的 `aria-label` 標明「已使用」），且畫面上以刪除線或降低不透明度呈現（不只靠顏色）；某點數四種花色都已使用時，該點數按鈕停用。
- 選完一張自動跳到下一個空牌位；全部填滿後自動關閉。也可按「完成」關閉（未填滿的牌位保持空白）。
- 每顆按鈕 `aria-label` 為完整名稱（例「黑桃 A」）。

| 下注金額 < 大盲且不是全下 | 最少要下注 $1.00（依 4.12 格式顯示大盲） |
| 加注到 < B + L 且不是全下 | 最少要加注到 $5.00（顯示 B + L） |
| 金額超過可用籌碼（A + S） | 金額超過可用籌碼 $79.50 |
| 下注 / 加注金額空白 | 請填寫金額 |
| 公牌未選滿就要開始該街行動 | 請選擇翻牌 3 張 / 請選擇轉牌 / 請選擇河牌 |

**完整模式：結果**

| 規則 | 錯誤訊息 |
| --- | --- |
| 攤牌對手沒選手牌也沒勾蓋牌 | 請選擇這位玩家的手牌，或標記為蓋牌 |
| 某個池的資格者都沒有手牌 | 這個底池至少需要一位玩家亮牌才能判定輸贏 |
| 抽水大於底池 | 抽水不可大於底池 |

### 5.6 標籤輸入

- 輸入框輸入文字後按 Enter 或「新增」鈕成為一個標籤（chip），chip 右側刪除鈕（`aria-label`「刪除標籤」）。
- 建議清單：同 v1 5.3 出資者名稱建議的規則（自製下拉、來源為所有手牌的 tags、去重不分大小寫保留最近寫法、依最近使用排序（該標籤出現過的手牌中最新的 playedAt，同時間依 createdAt）、部分符合篩選、排除本手已加的標籤、最多 8 筆）。

### 5.7 草稿

- 新增手牌頁（簡易與完整）有任何輸入時，內容自動存入 Settings.handDraft（輸入停止 500ms 後寫入）。內容包含模式、所有欄位的原始輸入字串、完整模式的目前步驟與已輸入的行動、公牌、攤牌選擇。
- 進入新增手牌頁時若有草稿：
  - 草稿的關聯場次與這次進入帶的 sessionId 相同（含都沒有）時，直接還原。
  - 不同時，跳出「有一手未儲存的手牌草稿，要繼續編輯嗎？」，選項「繼續草稿」（還原草稿，忽略這次帶的 sessionId）/「捨棄並重新開始」（刪除草稿，依這次的入口預帶）。
- 儲存成功、暫存為簡易成功、或按右上角「清除」後刪除草稿。
- 草稿還原後若有不合法的內容（例如行動重播失敗），捨棄完整模式的行動部分、保留牌局設定，並提示「草稿中的行動無法還原，已保留牌局設定」。
- 編輯模式不讀寫草稿（同 v1 5.7）。

### 5.8 儲存、編輯與補齊

**儲存後行為（新增）**

- 寫入成功後顯示提示「已儲存手牌」（完整手牌加結果，例「已儲存手牌，你 +$84.00」），然後：從場次詳情進入者返回場次詳情；其餘返回手牌列表。
- 完整模式儲存時更新 Settings.lastHandSetup（gameType、tableSize、sb、bb、ante、straddle、預設籌碼、你的座位）。
- 新手牌配發 exportSeq（7.4），與手牌寫入在同一個 transaction。
- 寫入失敗：顯示「儲存失敗，請再試一次」，表單內容不清空。儲存處理中按鈕停用並顯示載入狀態（同 v1 5.5）。

**編輯（手動手牌）**

- 標題「編輯手牌」，沿用新增的元件；不讀寫草稿、不更新 lastHandSetup。
- 簡易備忘手牌（detail 為 null）：可修改 5.2 所有欄位；另有「補齊為完整手牌」按鈕（見下方）。
- 有 detail 的手牌（完整或未完成）：開啟完整模式，進度停在最後狀態。
  - 修改時間、關聯場次、標籤、備註、你的手牌、公牌、攤牌牌：直接改（仍需符合牌不重複）。
  - 修改牌局設定的其他欄位（人數、盲注、前注、straddle、座位、籌碼、按鈕、你的座位、牌局類型）：若已有行動，跳出確認「修改牌局設定會清除所有已輸入的行動，確定嗎？」，確定後清除 actions、collected 與攤牌選擇，公牌保留。
  - 修改行動：只能用「復原上一步」退回後重新輸入。
- 儲存後依 3.9 重新判定 kind；更新 updatedAt；id、exportSeq、createdAt 不變；返回手牌詳情。
- 有未儲存變更時按返回，跳出「放棄變更？」確認（同 v1 5.7）。

**補齊為完整手牌（H3）**

- 簡易備忘手牌詳情與編輯頁有「補齊為完整手牌」按鈕，開啟完整模式步驟 1，預填：時間、關聯場次、牌局類型、標籤、備註、你的手牌、大盲（若有；小盲預填大盲 ÷ 2 捨入到最小單位）、公牌（暫存，進入對應街時預填，可修改）。若有位置，依該位置在預設人數下推算按鈕座位（你在 lastHandSetup 的座位，按鈕放在使該座位成為該位置的座位）；推算不出（例如位置在該人數不存在）時不預填按鈕。
- 備忘的「結果」不預填（完整手牌的結果由行動計算）；儲存為完整時備忘的 heroNet 被計算值取代。
- 儲存後同一 id，kind 變為 complete（或未完成時維持 simple 並帶 detail）。

**匯入的手牌（source 為 gg）**：只能修改關聯場次、標籤、備註；牌局內容與時間鎖定，編輯頁上方顯示「匯入的手牌只能修改關聯場次、標籤與備註」（14 節 HQ17）。

### 6.4 刪除手牌與復原

比照 v1 7.5：

- 按刪除跳出確認視窗，內容包含時間、Hero 手牌、位置、結果。
- 確認後從 DB 實體刪除，返回上一頁（列表或場次詳情），底部顯示「已刪除 · 復原」提示 5 秒。
- 按復原時，以原始 id、exportSeq、createdAt、updatedAt 及所有欄位原封不動寫回。若原本關聯的場次在這段時間內被刪除，sessionId 改為 null 後寫回。
- 不提供多選批次刪除。

### 6.5 刪除場次時的手牌（v1 7.5 的變更）

- 場次刪除確認視窗：該場有手牌時加一行「這場有 3 手手牌，刪除後會轉為獨立手牌（不會刪除）」。
- 確認後，在同一個 Dexie transaction 內：刪除場次，並把所有 sessionId 等於該場的手牌改為 sessionId = null。轉為獨立**不更新**手牌的 updatedAt（屬系統連帶變更；刪除場次本來就不觸發備份提醒，v1 8.7）。
- 「已刪除 · 復原」：在同一個 transaction 內寫回場次，並把**這次刪除時被轉為獨立、且目前 sessionId 仍為 null** 的手牌改回原 sessionId（依刪除時記下的手牌 id 清單）。

## 7. 匯出（PokerStars 格式）

### 7.1 匯出流程

- 入口：手牌列表的「匯出」（匯出目前篩選結果中的完整手牌）、手牌詳情的「匯出這手」。
- 按下後開啟 bottom sheet「匯出手牌」，非同步讀取並組好文字（顯示「準備中…」），內容：
  - 「將匯出 80 手完整手牌」。
  - 篩選結果含簡易手牌時：「簡易手牌 40 手無法匯出，已略過」（簡易手牌一律不匯出、不報錯）。
  - 0 手完整手牌時顯示「沒有可匯出的完整手牌」，不顯示匯出按鈕。
  - 超過 10,000 手時顯示「一次最多匯出 10,000 手，請縮小篩選範圍」，不顯示匯出按鈕。
  - GTO Wizard 提示（7.8）。
  - 按鈕「分享 / 下載」。
- 匯出順序：依 playedAt 由舊到新，同時間依 exportSeq 由小到大。
- 匯出方式同 v1 8.4：`navigator.canShare({ files })` 可用時開啟分享選單，否則 Blob 下載。
- 必須：iOS 的 `navigator.share` 必須在使用者手勢的同步路徑內呼叫。文字在 sheet 開啟後就預先組好，按「分享 / 下載」時同步建立 File 並呼叫 `src/lib/shareFile.ts`（v1 既有），中間不得有任何 await。失去使用者手勢（NotAllowedError）時提示「請再按一次」；使用者取消分享不提示。
- 匯出不改變任何資料（不更新 lastBackupAt、不更新手牌）。

### 7.2 檔案

- 檔名：`poker-hands-YYYYMMDD-HHmm.txt`（本地時間）；單手匯出為 `poker-hand-<匯出編號>.txt`。
- MIME：`text/plain`。
- 編碼：UTF-8，**不加 BOM**（**需驗證**，14 節 HQ13）。檔案內容只會出現 ASCII 字元（名稱、牌面、數字、格式字串都限制為 ASCII，7.3），所以有無 BOM 都不影響內容。
- 換行：`\n`（**需驗證**，14 節 HQ13）。
- 手牌之間：前一手最後一行之後空**兩行**，再接下一手的標頭（即兩手之間有 2 個空行）。檔案最後一手之後以單一 `\n` 結尾（**需驗證**，14 節 HQ13）。

### 7.3 玩家名稱

**Hero 名稱（H4）**：設定頁「手牌」區塊「匯出名稱」輸入框，存入 Settings.handHeroName。

- 規則（必須，保守定義）：1–12 個字元；只允許英文字母 `A–Z a–z`、數字 `0–9`、底線 `_`；第一個字元必須是英文字母；正規表示式 `^[A-Za-z][A-Za-z0-9_]{0,11}$`。這排除了冒號、方括號、圓括號、空白、`#`、`$`、換行與非 ASCII 字元，避免破壞 `Seat n: <name> (...)`、`<name>: folds` 等行的格式。
- 不可為 `Villain` 加數字（不分大小寫，`^villain\d+$`），避免與對手名稱衝突。
- 錯誤訊息：「名稱需為 1–12 個英文字母、數字或底線，且以英文字母開頭」「不可使用 Villain 加數字的名稱」。
- 儲存後即時生效於之後的匯出；既有手牌不需重算。
- 輸入框旁小字：「匯出給 GTO Wizard 等工具時，你在手牌中的名稱」。

**對手名稱**

- 預設 `Villain<座位號>`，例座位 6 為 `Villain6`。
- GG 匯入的手牌：Seat.name 不為 null 時沿用原站匿名名稱（14 節 HQ9）。
- 衝突處理（必須）：產生名稱後若同一手內有兩位玩家名稱相同（不分大小寫），或對手名稱與 Hero 名稱相同（不分大小寫），後者（座位號較大者；與 Hero 衝突時為對手）改用 `Villain<座位號>`。
- Seat.name 寫入條件：符合 `^[A-Za-z0-9_]{1,20}$` 且不符合 `^villain\d+$`（不分大小寫），否則存 null。

### 7.4 手牌編號

- 匯出的手牌編號 = `77` + exportSeq 補零到 14 位，共 16 位數字。例：exportSeq 1 → `7700000000000001`。
- exportSeq 配發（必須）：新增或匯入手牌時，next = max(Settings.lastHandSeq, hands 表最大 exportSeq) + 1，與手牌寫入、lastHandSeq 更新在同一個 transaction 內完成。lastHandSeq 只增不減，刪除手牌後序號不重用，避免同一編號在不同時間代表不同手牌（外部工具多以編號去重，重用會讓新手牌被當成重複而略過）。
- 避免與真實站點混淆：PokerStars 實際手牌編號目前約 12 位數；本 App 的編號固定 16 位且以 `77` 開頭，最大值 7,799,999,999,999,999 小於 `Number.MAX_SAFE_INTEGER`。GG 匯入的手牌也使用本 App 的編號，不沿用原站編號（14 節 HQ8）。
- 錦標賽的賽事編號（7.7 第 1 行）使用同一個 16 位編號（14 節 HQ11）。

### 7.5 時間與時區

- v1 與本文件的時間都以本地時間儲存、不含時區。匯出時（必須）：把 playedAt 視為**匯出當下裝置時區**（`Intl.DateTimeFormat().resolvedOptions().timeZone`）的本地時間，換算成美東時間（IANA `America/New_York`，自動處理夏令時間），以 `YYYY/MM/DD HH:mm:ss ET` 輸出（14 節 HQ2，格式**需驗證**）。
- 例：裝置時區 Asia/Taipei，playedAt `2026-10-01T09:15:00` → `2026/09/30 21:15:00 ET`（美東夏令 UTC−4）。
- 本地時間不存在（夏令時間跳過的那一小時）時，依 JavaScript `Date` 的行為往後推；本地時間重複（夏令時間結束）時取較早的那一次。台灣沒有夏令時間，不會遇到。
- GG 匯入的 playedAt 是原文時間，原文時區未知（14 節 HQ16），匯出時同樣視為裝置時區。

### 7.6 金額格式（匯出檔）

| 牌局 | 格式 | 例 |
| --- | --- | --- |
| 現金桌 | `$` + 整數部分（無千分位）+ `.` + 2 位小數 | 5 分 → `$0.05`、100 → `$1.00`、1234567 → `$12345.67` |

## 8. GG 匯入（實驗功能）

**本節依公開資料撰寫，撰寫時沒有真實 GG 匯出檔。** 所有格式描述都屬「需驗證」；取得真實檔案後必須補驗證與測試 fixture（14 節 HQ15），在那之前畫面一律標示「實驗功能」。

### 8.1 支援的輸入

| 輸入 | 說明 |
| --- | --- |
| 單一 `.txt` | 一個檔案可含多手 |
| 多個 `.txt` | 檔案選擇器 `multiple` |
| `.zip` | GG 的 PokerCraft 下載的壓縮檔，內含一或多個 `.txt`。以 fflate 解壓（建議，第 2 節） |

- 檔案選擇器 `accept=".txt,.zip,text/plain,application/zip"`，`multiple`。
- 限制（必須）：
  - 單次匯入所有檔案（zip 以解壓後計）合計 ≤ 50 MB 文字，超過時顯示「檔案太大，一次最多 50 MB，請分批匯入」並停止。
  - zip：只處理副檔名為 `.txt`（不分大小寫）的項目，忽略資料夾、其他副檔名與 `__MACOSX/`、檔名以 `.` 開頭的項目；巢狀 zip 不解壓；項目數 > 1,000 時停止並顯示「壓縮檔內的檔案太多（最多 1,000 個）」；解壓失敗顯示「無法解壓縮這個檔案」。
  - 文字解碼：UTF-8（`TextDecoder('utf-8')`，非 fatal），去除開頭 BOM；換行 `\r\n`、`\r` 一律正規化為 `\n`。

### 8.2 匯入流程

匯入頁 `#/hands/import`，標題「匯入 GG 手牌」旁有「實驗功能」標籤，下方說明：「GG 手牌格式依公開資料撰寫，尚未以真實檔案驗證。不支援的手牌會略過並說明原因，匯入後請抽查結果。」

1. **選擇檔案**：按「選擇檔案」。
2. **解析**：顯示進度「解析中 1,200 / 3,500 手」。解析分批進行，每批最多 200 手後讓出主執行緒（`setTimeout` 0 或 `scheduler.yield`），畫面不得凍結；可按「取消」中止，不寫入任何資料。
3. **預覽結果**（尚未寫入）：
   - 「可匯入 3,320 手 · 重複略過 150 手 · 無法匯入 30 手」。
   - 無法匯入的原因依原因分組計數（例「不支援 Run It Twice：12 手」），可展開看前 20 筆明細：原站手牌編號（取不到時為「第 3 個檔案第 18 手」）與原因。

   - 按鈕「匯入 3,320 手」；可匯入 0 手時不顯示此按鈕，只顯示「返回」。
4. **寫入**：在一個 Dexie transaction 內寫入全部可匯入的手牌並配發 exportSeq（7.4）；任何錯誤就整個還原，顯示「匯入失敗，沒有任何手牌被寫入」。成功後顯示「已匯入 3,320 手」並前往手牌列表（篩選來源 = GG）。

### 8.3 解析規則

**拆手**：以行首 `Poker Hand #` 為每手開頭，到下一個 `Poker Hand #` 或檔案結尾為止；去除每手前後的空行。每手的原文（正規化後）即 rawText；超過 20,000 字元的手拒絕（「手牌內容過長」）。不以 `Poker Hand #` 開頭的檔案內容（例如檔案開頭的雜訊）忽略。

**整體原則（必須）**：採**白名單**解析。每一行都必須符合下列其中一種格式，否則整手拒絕（「無法辨識的內容：第 N 行」，N 為該手內的行號）。解析後一律以 4.2–4.8 重播驗證；任何不一致即拒絕，**不得**猜測或略過不懂的內容。

| 區段 | 格式（正規表示式概念，金額 `<$>` 見下方） | 取得 |
| --- | --- | --- |
| 標頭 | `^Poker Hand #(?<prefix>[A-Z]{2})(?<num>\d+): Hold'em No Limit \(<$>/<$>\) - (?<date>\d{4}/\d{2}/\d{2}) (?<time>\d{2}:\d{2}:\d{2})$` | sourceHandId = prefix + num；sb、bb；playedAt = `YYYY-MM-DDTHH:mm:ss`（原文時間，不換算） |
| 牌桌 | `^Table '(?<name>[^']*)' (?<size>\d+)-max Seat #(?<btn>\d+) is the button$` | tableSize、buttonSeat |
| 座位 | `^Seat (?<no>\d+): (?<name>.+) \(<$> in chips\)$` | seats（只在 `*** HOLE CARDS ***` 之前） |
| 前注 | `^(?<name>.+): posts the ante <$>$` | ante（所有玩家必須相同，否則拒絕） |
| 小盲 / 大盲 | `^(?<name>.+): posts small blind <$>$`、`^(?<name>.+): posts big blind <$>$` | 必須與 4.1 推導的座位一致 |
| 發牌標記 | `^\*\*\* HOLE CARDS \*\*\*$` | |
| 發牌 | `^Dealt to (?<name>.+?)(?: \[(?<c1>\S{2}) (?<c2>\S{2})\])?\s*$` | 有牌的那一行即 Hero（下方） |
| 行動 | `^(?<name>.+): (folds\|checks\|calls <$>\|bets <$>\|raises <$> to <$>)( and is all-in)?$` | actions |
| 未跟注退回 | `^Uncalled bet \(<$>\) returned to (?<name>.+)$` | 驗證與 4.5 計算一致 |
| 各街標記 | `*** FLOP *** [a b c]`、`*** TURN *** [a b c] [d]`、`*** RIVER *** [a b c d] [e]` | board；轉牌、河牌行中前段公牌必須與先前相同 |
| 攤牌標記 | `^\*\*\* (SHOWDOWN\|SHOW DOWN) \*\*\*$` | 可有可無（**需驗證**：GG 是否在沒有攤牌時也輸出） |
| 亮牌 | `^(?<name>.+): shows \[(?<c1>\S{2}) (?<c2>\S{2})\](?: \(.*\))?$` | 括號內描述忽略 |
| 蓋牌 | `^(?<name>.+): mucks hand$` | mucked = true |
| 收回 | `^(?<name>.+) collected <$> from pot$` | collected（potIndex 0） |
| 摘要標記 | `^\*\*\* SUMMARY \*\*\*$` | |
| 底池摘要 | `^Total pot <$> \| Rake <$>(?: \| (?<fee>Jackpot\|Bingo\|Fortune\|Tax) <$>)*$` | rake = Rake + 所有附加費用合計；Total pot 必須等於 4.6 計算值 |
| 公牌摘要 | `^Board \[(.+)\]$` | 必須與各街公牌一致 |
| 座位摘要 | `^Seat \d+: .+$`（在 `*** SUMMARY ***` 之後） | 只辨識，不取值 |

- 金額 `<$>`：`\$(\d{1,3}(?:,\d{3})+|\d+)(?:\.(\d{1,2}))?`，換算成分（`$0.1` → 10、`$25` → 2500、`$1,000.5` → 100050）。千分位逗號是否出現**需驗證**。
- 金額有 3 位以上小數（`\$[\d,]+\.\d{3,}`）時，在白名單檢查之前就以「金額超過 2 位小數」拒絕。
- Hero 判定（必須）：`Dealt to` 行中帶 2 張牌的必須恰好 1 行，該玩家即 Hero；0 行或 2 行以上拒絕（「無法判定你的座位」）。Hero 名稱不必是 `Hero`。
- 名稱比對：行動、發牌、亮牌等行中的名稱必須是座位行出現過的名稱，否則拒絕。座位行中重複的名稱拒絕。
- 行動對應（必須）：
  - `calls X`：X 必須等於 4.3 的跟注金額。
  - `bets X`：to = X。`raises X to Y`：to = Y，且 Y − X 必須等於加注前的 B。
  - ` and is all-in`：必須與重播結果（剩餘籌碼 = 0）一致；重播為全下但沒有標記也拒絕。
- 收回與攤牌（必須）：
  - 4.6 切出 2 個以上的池（有邊池）→ 拒絕（「包含邊池，第一版暫不支援匯入」，14 節 HQ21）。
  - Σ collected + rake = Total pot，否則拒絕（「底池金額對不上」）。
  - 有攤牌且所有攤牌者都有亮牌時，收回者集合必須等於 4.7 判定的贏家集合，否則拒絕（「輸贏與牌力判定不符」）。有蓋牌者時，收回者必須是亮牌者中牌力最高者（含平手）。
  - 收回金額以原文為準，不依 4.8 重算（抽水分配方式與本 App 規則可能不同）。
- Seat.name 依 7.3 的寫入條件存原站名稱或 null；Hero 的 Seat.name 一律存 null（匯出時用 handHeroName）。
- 解析成功的手牌：source `gg`、parserVersion 1、gameType `cash`、straddle 0、kind 依 3.9 判定（解析成功即應為 complete；不完整的拒絕「手牌內容不完整」，不匯入成簡易手牌）、tags `[]`、note null、sessionId 依 8.2 選擇。

### 8.5 不支援的情況（必須明確拒絕）

在白名單解析之前，先以下列關鍵字檢查整手原文（不分大小寫），依表格由上到下的順序，取第一個符合者以對應訊息拒絕，讓原因更清楚；未列在此表的不支援情況，由白名單解析以「無法辨識的內容」拒絕。

| 情況 | 偵測（需驗證） | 拒絕原因（畫面文字） |
| --- | --- | --- |
| Omaha / PLO | 標頭含 `Omaha` 或 `PLO` | 不支援 Omaha（PLO），第一版只支援無限注德州撲克 |
| 短牌 | 標頭含 `Short Deck` 或 `6+` | 不支援短牌（Short Deck） |
| 非無限注 | 標頭不含 `Hold'em No Limit` | 只支援無限注德州撲克 |
| 錦標賽 | 前綴 `TM`，或標頭含 `Tournament` | 錦標賽手牌暫不支援匯入 |
| 未知前綴 | 前綴不是 `RC`、`HD` | 不支援的牌局類型（前綴 XX） |
| Run It Twice | `FIRST FLOP`、`FIRST TURN`、`FIRST RIVER`、`SECOND FLOP`、`SECOND TURN`、`SECOND RIVER`、`run it`、`two times` | 不支援 Run It Twice（發兩次牌） |
| EV Cashout | `Cashout`、`Cash Out` | 不支援 EV Cashout |
| 保險 | `Insurance` | 不支援保險 |
| Bomb Pot | `Bomb Pot`、`BombPot` | 不支援 Bomb Pot |
| straddle | `straddle` | 不支援 straddle（待真實檔案確認格式） |
| 補盲 | `missed blind`、`dead blind`、`small & big blind` | 不支援補盲（missed / dead blind） |
| 籌碼不足以支付盲注或前注 | 重播檢查（4.3） | 不支援玩家籌碼不足以支付盲注或前注的手牌 |
| 邊池 | 重播檢查（8.3） | 包含邊池，第一版暫不支援匯入 |
| 人數超出 | tableSize 不在 2–10、或座位數不在 2–tableSize | 不支援的牌桌人數 |
| 其他 | 白名單不符、重播不合法、金額不符、牌重複 | 無法辨識的內容：第 N 行 / 行動不合法：第 N 行 / 底池金額對不上 / 同一張牌不可重複出現 / 手牌內容不完整 |

### 8.6 重複匯入

- 判定（必須）：source 為 `gg` 且 sourceHandId 相同即為重複（以 `sourceHandId` 索引查詢）。
- 同一次匯入的多個檔案中出現同一 sourceHandId，第一次出現的計為可匯入，之後的計為重複。
- 重複的手牌一律略過，不覆寫既有手牌（既有手牌的標籤、備註、關聯場次保留）。

### 8.7 匯入結果摘要

- 預覽（8.2 步驟 3）與完成提示的數字定義：可匯入 = 解析成功且不重複；重複略過 = 8.6；無法匯入 = 8.5 拒絕。三者相加 = 拆出的總手數。
- 摘要只在匯入頁顯示，不另存紀錄。

## 9. PokerStars 解析器與往返測試

- 必須（範圍內）：實作 PokerStars 格式解析器 `parsePokerStars(text)`，至少能解析本 App 第 7 節輸出的**所有**變化（現金桌、錦標賽、前注、straddle、邊池、平分、全下自動發完、蓋牌、各種座位摘要）。

- 名稱還原：Hero 依 `Dealt to` 判定；`Villain<n>` 與 Hero 名稱以外的名稱存入 Seat.name（依 7.3 寫入條件）。

- 不提供使用者匯入 PokerStars 手牌的畫面（14 節 HQ19）；解析器只用於測試與日後擴充。

**往返測試（必須，12.2 HC18）**：

## 10. 備份與資料管理

### 10.1 備份檔格式（v1 8.4 的變更）

```
{
  "app": "poker-tracker",
  "schemaVersion": 3,
  "exportedAt": "2026-10-01T21:05:00+08:00",
  "sessions": [...],
  "venues": [...],
  "stakes": [...],
  "hands": [...],
  "settings": {...}
}
```

- schemaVersion：v2 起為 3。
- hands 每筆的欄位與 3.1 完全一致（含 detail、rawText），依 id 排序（同 v1 sessions 的固定順序原則）。
- settings 不包含 recordDraft、lastBackupAt、handDraft；包含 handHeroName、lastHandSeq、lastHandSetup（有值時）。
- 檔名、匯出方式、lastBackupAt 更新規則不變（v1 8.4）。

### 10.2 匯入（v1 8.5 的變更）

- 遷移（必須）：
  - 1 → 2：不變（v1 8.5）。
  - 2 → 3：設定 `hands: []`（v2 備份檔沒有此欄位；即使檔案中意外出現 `hands` 也一律覆寫為 `[]`，比照 1 → 2 的處理原則），其他欄位不變。
  - 1 版檔案依序執行 1 → 2 → 3。
- 檢查順序：v1 8.5 的順序，於「每筆資料通過 Zod 驗證」一步加入 hands，並在其後新增：
  1. 每筆 hand 通過 3.1–3.5 的 Zod 驗證。
  2. 每筆有 detail 的 hand 通過 3.9 結構驗證（行動重播合法、牌不重複）、kind 與 3.9 判定一致、摘要欄位與推導一致。
  3. hand 的 sessionId 存在於檔案的 sessions 中（或為 null），且類型相容（3.11）。
  4. exportSeq 不重複；source 為 gg 的 sourceHandId 不重複。
- 任一步失敗就停止，顯示失敗原因與第一筆有問題的資料位置，例：「第 12 筆手牌：行動不合法（第 5 個行動）」「第 3 筆手牌：關聯的場次不存在」。
- 確認視窗：「目前：N 場、H 手 / 備份檔：M 場、K 手（備份時間）」，警告文字不變。
- 匯入為完整取代（含 hands 表），在同一個 transaction 內。
- 匯入完成後：清除 recordDraft 與 handDraft；lastBackupAt 設為備份檔的 exportedAt；lastHandSeq 設為 max(檔案中的 lastHandSeq（沒有時為 0）, 檔案 hands 的最大 exportSeq)；顯示「已匯入 M 場紀錄、K 手牌」。
- v1.x 版本的 App 匯入 schemaVersion 3 的檔案會因「schemaVersion 過新」被拒（v1 既有規則），這是預期行為。

### 10.3 Zod 與錯誤代碼

- hands 的 Zod schema 放在 `domain/hands/schemas.ts`；備份驗證（`domain/backup.ts`）的 `BackupCollection` 加入 `'hands'`，錯誤代碼沿用既有 `invalidRecord`、`duplicateId`、`missingReference`，另新增 `invalidHandDetail`（結構驗證失敗，附行動序號）、`duplicateExportSeq`、`duplicateSourceHandId`。`CURRENT_SCHEMA_VERSION` 改為 3，`BACKUP_MIGRATIONS` 加入 2 → 3。

### 10.4 CSV

- v1 8.6 的場次 CSV **不加入**手牌欄位（不加手牌數，以免欄位位置改變影響使用者既有試算表）。
- v2.0 **不提供**手牌 CSV（手牌的匯出用途由 PokerStars `.txt` 滿足；14 節 HQ22）。

### 10.5 備份提醒（v1 8.7 的變更）

- 條件 1 改為：從未備份過，且「場次數 + 手牌數」≥ 10。
- 條件 2 改為：距上次備份超過 30 天，且備份後有場次**或手牌**被新增或修改（任一 updatedAt > lastBackupAt）。
- 刪除手牌、刪除場次造成的手牌轉為獨立，不觸發（同 v1 已知限制）。

### 10.6 其他設定頁變更

- 8.8 資料量：加「手牌數（完整 / 簡易）」，例「手牌 120（完整 80 / 簡易 40）」。
- 8.9 清除所有資料：一併清除 hands 表與 handDraft。
- 設定頁新增「手牌」區塊（位於「顯示設定」之後、「備份」之前）：匯出名稱（7.3）、「匯入 GG 手牌（實驗功能）」入口。
